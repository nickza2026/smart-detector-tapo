# คู่เสียงหลังกลับจากช่วงเสียงขาด

การแก้ในซอร์สหลัง V53 นี้เก็บ Ready และ End ที่รับต่อเนื่องหลัง gap เป็นความสัมพันธ์ของ **หลักฐานบางส่วน** แสดงหนึ่งแถว ไม่ใช่การยืนยันว่าเป็นลูกค้าคนเดียวกันหรือสร้างรอบเติมที่สมบูรณ์

- ตัวอย่าง gap → Ready 14:52:37 → End 14:52:50 แสดงเวลา Ready/End ในแถวเดียว พร้อมสถานะข้อมูลรอบไม่ครบ จำนวนครั้งคือ Ready ที่ยืนยันได้ ไม่ใช่จำนวนการหยอดหรือยอดเงิน
- รอบก่อน gap ยังคง interrupted ไม่มีการย้อนใส่ End ให้รอบเก่า ไม่มี session, issue, image หรือ outbox/API job ใหม่จากคู่บางส่วนนี้
- บันทึก association แยกจาก `sessions` และ checkpoint ชั่วคราวในธุรกรรมเดียวกับ observations เปิดอ่านฐานอีกครั้งยังติดตามคู่เดิมได้ หากเกิด gap ใหม่แม้ไม่มี canonical session ที่เปิดอยู่ จะตัด candidate ทันที
- ไม่รวม Ready ที่เกิดก่อนขอบเขต gap ไม่เพิ่มจำนวนจาก source key ซ้ำหรือประกาศที่ทับซ้อนซึ่ง engine ปฏิเสธ หากเลย completion deadline เดิมห้านาทีจาก Ready ล่าสุดจะไม่ใช้ candidate เก่าจับ End; ไม่เปลี่ยนกติกาของรอบปกติ
- เมื่อ End ใช้เป็นขอบเขตแล้ว รอบปกติถัดไปทำงานตามเดิม การอ่านประวัติไม่เขียน backfill จำกัดผลลัพธ์เดิมที่ 200 แถว และไม่ตัดคู่เป็นสองแถวแม้ขอหนึ่งรายการ
- association อ้าง observations แบบลบตามกันและหมดอายุพร้อมข้อมูลสามวัน ส่วน candidate มีอายุสามวันนับจากการสร้าง ไม่ต่ออายุด้วย Ready ซ้ำ ไม่เก็บ source key ในข้อมูลที่ส่งให้ตาราง ไม่ร้องขอรูปโดยใช้ ID ของคู่บางส่วน

ข้อมูลเก่าก่อนมี association อาจไม่เก็บเหตุ gap ซ้ำระหว่าง Ready/End ไว้ครบ จึงไม่เดารวมจากระยะเวลาใกล้กันย้อนหลัง ภาพที่ส่งมาเพียงอย่างเดียวไม่เพียงพอให้แก้ฐานจริง และไม่มีการเชื่อมต่อหรือแก้ฐาน VPS ในงานนี้

การแก้นี้เป็นส่วนของ V54 ไม่เปลี่ยน EXE V53 ที่เผยแพร่ไปแล้ว และไม่ได้แก้ฐานหรือข้อมูลประวัติบน VPS ย้อนหลัง
