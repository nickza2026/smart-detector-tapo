# Diagnostic .9 — ตรวจอุปกรณ์จริงและไม่ใช้ XML เก่าค้าง

ภาพที่ผู้ใช้ส่งยืนยันว่าเป็นหน้าPlayback (มีวันที่/แถบเวลา) แต่รายงาน.8สองไฟล์มี75nodes/activityเหมือนกัน ต่างเพียงoperator_label **จึงห้ามใช้คู่นี้สร้างกติกาว่าLive/Playbackแยกกันได้** ยังไม่ยืนยันว่าสาเหตุบนVPSคือXMLเก่า/เลือกคนละinstance/ข้อจำกัดaccessibility

## ช่องผิดพลาดในโค้ดที่reproduceได้

1. `uiautomator dump`อาจรายงานerrorแต่exit0 โค้ดเดิมอ่านชื่อไฟล์คงที่แล้วได้Live XMLของครั้งก่อน
2. ใช้ไฟล์ชื่อเดียวข้ามคำขอและไม่ลบที่ชั้นadapter ทำให้cache/คำขอชนกันได้
3. dumpsysมีresumedหลายบรรทัด โค้ดเดิมเลือกTapoตัวแรกแทนtop-resumedจริง อาจอ่านactivityพื้นหลัง

มีregressionที่failก่อนแก้ตามสาเหตุแล้ว แก้เป็นUUIDใหม่ทุกคำขอ ตรวจerrorแม้exit0/ขนาด/valid hierarchy ลบเฉพาะไฟล์ของคำขอในfinally ไม่อ่านชื่อเก่า; receiptเกิดหลังสำเร็จทั้งหมดเท่านั้น foregroundเลือกtopก่อน ไม่fallbackไปTapoพื้นหลังเมื่อtopเป็นแอปอื่น และถ้ากำกวมให้unknown

ไม่ได้ต่อADBจริงจากเครื่องพัฒนา การแก้นี้พิสูจน์กลไกด้วยmock ไม่ใช่ผลยืนยันว่าบนVPSแก้แล้ว

## ขั้นตอนบน MEmu

1. ปิด.8แล้วเปิด.9 ใช้configเดิม หยุดCapture/Worker/การรับเสียง
2. เปิดPlaybackในTapoให้เห็นแถบเวลาเหมือนภาพที่ส่งมา
3. ที่SmartTapoแท็บ **3. เริ่ม / หยุด** กด **ดูภาพอุปกรณ์ ADB (ไม่บันทึก)**
   - ภาพต้องตรงหน้าที่กำลังดูในMEmu ถ้ากลับเห็นLiveหรือคนละกล้อง/instance ให้กลับแท็บตั้งค่าเลือกADB Serialให้ตรงและบันทึกก่อน อย่าใช้รายงานจากอุปกรณ์ที่ไม่ตรง
   - ปุ่มนี้อ่านscreencapของSerialที่เลือกเข้าRAMเฉพาะเมื่อกด ไม่เปิดMEmu/launchTapo/นำทางหรือบันทึกภาพ ไม่ใช่ปุ่มถ่ายภาพcalibrationเดิมซึ่งอาจนำทางไปLive
4. เมื่อภาพตรง กด **เก็บหน้า Playback** รอเสร็จ ถ้าอ่านhierarchyใหม่ไม่ได้จะไม่ส่งออกไฟล์เก่า ลองพักวิดีโอชั่วครู่โดยยังอยู่หน้าPlaybackแล้วเก็บอีกครั้งได้
5. สลับTapoไปLiveจริง กด **เก็บหน้า Live** ส่งJSONใหม่2ไฟล์จาก **เปิดโฟลเดอร์รายงานหน้า** กลับมาตรวจ ไม่ใช้.8เป็นnegative/positiveที่ยืนยันแล้ว
6. กลับTapoไปLiveก่อนใช้Capture/Workerเดิม

## รายงานv2

- แยกจากAPIประวัติเติมv1 ซึ่งไม่เปลี่ยนสัญญา
- เพิ่มcollector_build,selected_serial_sha256(ไม่ส่งSerialตรงๆ),xml_request_idและfresh_transportเพื่อแยกชุด/อุปกรณ์และรู้ว่าอ่านไฟล์ใหม่สำเร็จหรือไม่
- fresh_transportยืนยันเพียงtransportไฟล์ใหม่ ไม่ยืนยันว่าLive/เป็นกล้องที่ต้องการ/แยกเสียงTapoจากแอปอื่นได้ verified_modeยังเป็นunknownและoperator_labelยังเป็นป้ายที่คนเลือก
- รายงานไม่มีภาพ/rawXML/free-textบัญชี/ชื่อกล้อง มีเพียงresource/control markers/activityและcamera-presence boolean ไม่อัปโหลดเอง ภาพpreviewไม่บันทึกหรือส่งในรายงาน
- Adapterใช้XMLชั่วคราวในAndroidและพยายามลบไฟล์ของตน ถ้าADB/cleanupล้มเหลวไม่รายงานสำเร็จ ไม่รับประกันphysical eraseเมื่ออุปกรณ์ขาดการเชื่อมต่อ
