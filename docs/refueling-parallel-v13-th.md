# SmartTapo .13 — Capture + Worker + ฟังเสียง และกู้ Tap to refresh

รุ่น `2026-10-30.13` แก้ข้อจำกัดที่เปิดเสียงก่อนแล้วเริ่ม Capture/Worker ไม่ได้ ทั้งสามงานเริ่มร่วมกันได้โดยใช้การตั้งค่ากล้องและโฟลเดอร์ข้อมูลเดิม ระหว่างทำงานยังไม่อนุญาตให้เปลี่ยนการตั้งค่าไปเป็นอีกกล้อง/อีกชุดข้อมูล

## อัปเดตบน VPS โดยไม่ทิ้งประวัติ

ไฟล์ที่สร้างบนเครื่องพัฒนา **ยังไม่ได้ถูกส่งไป VPS อัตโนมัติ**:

```text
D:\works\smart-detector-tapo\.tools\SmartTapo-v13-parallel-recovery.zip
```

1. คัดลอก ZIP จากเครื่องพัฒนาไป VPS แล้วแตกในโฟลเดอร์ชั่วคราว
2. ใน SmartTapo เดิมกดหยุดทั้งหมด รอให้ Capture/Worker/เสียงหยุด แล้วปิดโปรแกรม
3. แทนเฉพาะ `SmartTapo.exe` ในโฟลเดอร์ใช้งานเดิมด้วย EXE ใหม่ อย่าเปิดตัวเก่ากับตัวใหม่ซ้อนกัน
4. **ไม่ลบ config, data, รูปอ้างอิง, โปรไฟล์เสียง หรือประวัติเดิม** ไม่ต้องเปลี่ยนโฟลเดอร์ข้อมูลเพื่ออัปเดต
5. เปิด EXE ในบัญชี Windows เดิม ถ้าใช้ `config.local.json` ข้าง EXE ให้รักษาไฟล์นั้นไว้ ถ้าใช้ค่าปริยาย ข้อมูลยังอยู่ใต้ `%LOCALAPPDATA%\SmartTapo` ของบัญชีเดิม
6. ตรวจข้อความสถานะหลังเริ่ม Capture/Worker ต้องระบุ `2026-10-30.13`

ZIP มีชุด `prepared-profile` ที่เตรียมไว้เดิมให้ด้วย หากติดตั้งโปรไฟล์ไว้แล้วให้ใช้โปรไฟล์เดิม ไม่ต้องสร้างใหม่หรือป้อนค่าซ้ำ คีย์ Windows ที่เข้ารหัสผูกบัญชีเดิม ไม่ควรคัดลอกไปใช้ต่างบัญชีแล้วคาดว่าจะเปิดได้

## เปิดสามงานร่วมกัน

ทำใน **VNC/Console** ที่เห็นอุปกรณ์ CABLE และให้ MEmu กับ SmartTapo อยู่ใน session เดียวกัน ใช้อย่างละชุดเดียว

1. เปิด MEmu/Tapo ที่หน้า **Live ของกล้องที่ตั้งไว้** และเปิดเสียงกล้อง ไม่ใช่ Playback
2. Windows ส่งเสียง MEmu ไป **CABLE Input** ตัวปกติ ไม่ใช่ CABLE In 16ch หากเปลี่ยน output หลังเปิด MEmu อาจต้องปิด/เปิด MEmu ใหม่หนึ่งครั้ง
3. เริ่ม **Capture** ตามปกติ แล้วเริ่ม **Worker** โดยใช้ภาพอ้างอิงช่องว่างที่ยืนยันไว้แล้ว
4. แท็บเสียง เลือก **CABLE Input … [Loopback]** เลือกโปรไฟล์เดิม ยินยอม แล้วกดเริ่มฟังประวัติต่อเนื่อง **ครั้งเดียว**

จะเริ่มเสียงก่อน Capture/Worker ก็ได้ รุ่นนี้ไม่ล็อกลำดับนั้นอีก แต่ทุกส่วนใช้ค่ากล้องเดิมที่ตรึงไว้ขณะเริ่ม ไม่มีการเปิดฟังเองเมื่อเปิด EXE และไม่มีการสลับไปไมโครโฟนหรืออุปกรณ์อื่นเอง

- ปุ่มหยุดของแต่ละงานหยุดงานนั้นได้ ส่วน **หยุดทั้งหมด** หยุดทั้งสามส่วน
- ทดสอบเสียง 10 วินาทียังคงแยกจากตัวฟังต่อเนื่อง ไม่เปิดทดสอบกับตัวฟังเสียงต่อเนื่องซ้อนกัน
- หากจะเล่นคลิปย้อนหลังทดสอบ ให้หยุดการเฝ้าจริงก่อน ไม่ควรนำ Playback มาเป็นเหตุการณ์เติมจริง

## เมื่อขึ้น Tap to refresh

ระบบจะยอมกด refresh เฉพาะเมื่ออ่านหลักฐานใหม่ได้ว่าเป็น Tapo หน้า Live ของกล้องที่เลือก มีข้อความ `Tap to refresh` เพียงเป้าหมายเดียว และตำแหน่งอยู่ภายในภาพวิดีโอที่ตั้งไว้

- ไม่เดาจุดกดจากพิกัดตายตัว ไม่กดปุ่ม Alarm Off/Light/Privacy Mode และไม่กรอกรหัสผ่าน
- ไม่กด refresh ผ่านหน้า Playback กล้องผิดตัว หน้าล็อกอิน หรือหน้าที่ระบุไม่ได้
- จำกัดไม่เกินสามครั้งต่อหนึ่งรอบกู้ มีช่วงรอและรองรับการหยุด หากยังไม่กลับ Live งานเฝ้าจะรอ/ลองใหม่ตามรอบของแต่ละงาน ไม่ถือว่ากดสำเร็จเท่ากับภาพกลับมาแล้ว
- ช่วงกู้จะไม่ใช้ภาพก่อนกู้ต่อเป็นชุดยืนยันแบงก์ค้าง และไม่ต่อเสียงก่อน/หลังช่วงที่ไม่ทราบสถานะให้เป็นเหตุการณ์เดียวกัน ต้องยืนยัน Live ใหม่ก่อนรับผลต่อ
- รอบเสียงที่ขาดอาจเป็น `interrupted` โดยไม่แต่งเวลาเติมจบ ส่วนประวัติ/ผลส่งที่ยืนยันไปก่อนหน้าไม่ถูกลบทิ้ง การแจ้งเตือนที่ส่งออกไปแล้วไม่สามารถเรียกคืนได้
- ภาพ spool จากก่อนเริ่มระบบ Windows รอบปัจจุบันหรือรูปแบบเก่าที่ไม่มีหลักฐานรอบระบบ จะไม่ถูกยกเป็นภาพสดเพื่อส่งเตือน

**ข้อจำกัดสำคัญ:** ใช้ข้อความและตำแหน่งจาก accessibility ของ Tapo ไม่ใช่ OCR จากภาพที่ผู้ใช้ส่ง หาก Tapo รุ่นนั้นวาดข้อความไว้ในภาพแต่ไม่เผยแพร่ให้ตรวจ หรือเปลี่ยนภาษา/หน้าตา ระบบจะไม่เดากดเอง ไม่ควรถือว่า screenshot เพียงใบเดียวพิสูจน์ว่าการกู้บนเครื่องจริงผ่านแล้ว การเปิด Tapo/ล็อกอิน/เปิดกล้องครั้งแรกยังเป็นหน้าที่การเตรียมเริ่มงาน ไม่ได้เพิ่มการสุ่ม Back หรือเปิดกล้องจากหน้าไม่รู้จัก

## VNC กับ RDP

เครื่องนี้มีหลักฐานว่าขณะใช้ RDP รายการดิบเห็นเฉพาะ Remote Audio ส่วนผู้ใช้รายงานว่า VNC เห็น CABLE และมิเตอร์ขยับแล้ว จึงแนะนำใช้ VNC ดูแลขณะเฝ้า ไม่สลับเข้า RDP ด้วยบัญชีเดียวกันระหว่างงาน เพราะอาจย้าย session และทำให้อุปกรณ์/เส้นทางเสียงเปลี่ยน

การปิดเฉพาะหน้าต่าง VNC ไม่ใช่ Sign out แต่ **ยังต้องตรวจการรับเสียงหลังปิด Viewer จริง** รวมถึงพฤติกรรมล็อกหน้าจอ/เครือข่ายของ VPS ไม่ถือว่าการทดสอบจำลองรับรองความต่อเนื่องทุกสภาพ

## สิ่งที่ทดสอบและยังไม่ยืนยัน

ชุดพัฒนาทดสอบหน้ากู้จำลอง, การเปลี่ยนรุ่นหลักฐานระหว่างวิเคราะห์เสียง, Stop ระหว่างรอ lock, ภาพก่อน reboot/นาฬิกาย้อน และการใช้สาม process ร่วมกันใน GUI จริงนอกจอ โดยใช้ PCM/ADB จำลองกับฐานข้อมูลชั่วคราวและไม่ส่งแจ้งเตือนจริง

ยังไม่ใช่ผลรันสามงานพร้อมกันบน VPS จริง ไม่รับรองว่า Tap to refresh ของเครื่องจริงเปิดเผย accessibility ครบ ไม่ใช่การวัดความแม่นยำกับเสียงลูกค้าจริง และไม่ได้ยืนยันการส่ง Pushover ถึงโทรศัพท์หรือการส่งข้อมูล dashboard ใหม่
