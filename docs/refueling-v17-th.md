# SmartTapo .17 candidate — กู้คำถาม 5 นาทีต่อด้วยรีเฟรชภาษาไทย

รุ่น `2026-10-30.17` แก้เส้นทางกู้ในโค้ด ไม่ใช่การรับรองว่าปัญหาบนเครื่องจริงหรือ VPS ของภาพที่รายงานกู้ผ่านแล้ว

## สิ่งที่แก้

- รู้จักทั้ง `Tap to refresh` และ `แตะเพื่อรีเฟรช` เมื่ออ่านเป็น text/content-desc ได้จาก UI hierarchy ไม่ถือว่า Live เพียงเพราะปุ่มควบคุมยังอยู่ด้านหลัง overlay
- หลังคำถามดูต่อครบ 5 นาที ถ้ากดต่อแล้วพบรีเฟรช จะตรวจ activity/ชื่อกล้อง/เป้าหมายใหม่และกู้ขั้นนั้นต่อ ภายในจำนวนขั้นที่จำกัด ต้องอ่าน Live ครบจริงหลังการแตะ ไม่ถือว่าการกดปุ่มคือสำเร็จ
- ลด UI dump ที่ซ้ำกันก่อนกด โดยรอ UI lock และ decision lock **ก่อน** อ่าน evidence ที่ใช้ตัดสิน ไม่เก็บพิกัดก่อนรอแล้วนำกลับมาใช้ สิทธิ์เดิมยังมีอายุสูงสุด 10 วินาทีจาก request start ไม่ขยาย TTL เพื่อกลบปัญหา
- Continue ใช้สิทธิ์ได้ครั้งเดียว ต้องมี selected-camera Live จริงล่าสุดใน session/config/generation เดียวกัน Stop/กล้องผิด/หน้าอ่อนไหว/Playback/เป้าหมายไม่ชัด/หมดอายุยังห้ามกด ไม่เดา Home/Back และไม่กด Talk/Alarm
- ถ้าเริ่มมาเจอ modal โดยยังไม่เคยยืนยันกล้องหรือหลักฐานหมดอายุ จะไม่กดผ่านให้เอง ต้องเปิด Live กล้องที่ถูกต้องก่อนเริ่มหนึ่งครั้ง ไม่ใช่การยืนยันว่ากู้หน้าไม่รู้จักได้ทุกกรณี
- ถ้า refresh เป็นภาพวาดที่ไม่มี accessibility text/bounds จะไม่เดาตำแหน่งจากภาพ ต้องมี hierarchy ของ layout นั้นเพื่อขยายการรองรับอย่างปลอดภัย
- แก้ข้อความ retry ของ .16 ที่เคยแสดง delay `0/.25/.5` ผิดเป็น30วินาที ให้ตรงกับ backend; policy retryเร็วเดิมและข้อจำกัดตาม `refueling-v16-th.md` ไม่เปลี่ยน

เมื่อมี navigation ภาพ/เสียงก่อนหน้าต้องไม่ถูกนำมาต่อเป็นหลักฐาน Live หลังกลับมา ช่วงเสียงขาดยังไม่ใช่การรับเสียงต่อเนื่อง ไม่สร้าง end ปลอม ไม่อนุมานลูกค้า/เงินที่ไม่ได้เห็น หากพลาดทั้งเสียงเริ่มและจบอาจไม่มีรายการรอบนั้นในประวัติ

## หลักฐานและขอบเขต

Regression ล้มก่อนแก้: Thai refresh ถูกจัดเป็น Live ผิด, กด Continue ครั้งเดียวแล้วจบแม้ยังมี overlay และ UI cost จำลอง1.3วินาทีทำให้การอ่านซ้ำกินสิทธิ์10วินาทีก่อนกด ผ่านหลังแก้ โดยยังทดสอบ expiry/Stop/กล้องผิด/เพื่อนเปลี่ยน generation/พิกัดเปลี่ยนระหว่างรอ lock ทั้งหมด

ชุดทดสอบใช้ native sanitized fixture ของ modal ที่เก็บก่อนหน้า ร่วมกับ synthetic transition/Thai label ตามภาพที่ผู้ใช้ส่ง ไม่ได้อ้างว่าเป็น native hierarchy ของ refresh ภาษาไทยของภาพล่าสุด

Readonly ADB probe ครั้งนี้บน **เครื่องหลัก** พบ selected-camera layout Live ไม่มี modal ใน hierarchy ไม่ได้กดปุ่ม ไม่เปิดเสียง/ไมค์ ไม่ส่งแจ้งเตือนหรือเปลี่ยน foreground จึงไม่ใช้ผลนี้อ้างว่ากู้ modal ตามภาพสำเร็จ ยังรอยืนยันว่าภาพมาจากเครื่องหลักหรือ VPS และยังไม่ได้เข้าถึง VPS

ผล fullsuite/clean-source/frozen EXE และ SHA256 ให้ตรวจ receipt ที่สร้างจริง ไม่ใช้ focused tests หรือ compile แทน acceptance บนเครื่องจริง การ smoke ใช้ synthetic PCM/SQLite และ GUI นอกขอบทุกจอ ไม่มี hardware/ADB/เสียงจริง

## สิ่งที่ยังไม่ยืนยัน

ยังไม่ได้ทดสอบ native modal→Thai refresh→Live ครบวงจรของภาพล่าสุด, ความต่อเนื่องเสียง/เวลารวมกู้จริง, closed-Viewer บน VPS, ประกาศลูกค้าจริงครบวงจร หรือโทรศัพท์/ธุรกรรม ไม่ลด strict10ภาพ/gap/audio2s ไม่เปลี่ยน Windows audio/driver/service ไม่ใช้เงินจริง และไม่มี commit/push
