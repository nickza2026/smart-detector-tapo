# V44: แยกข้อผิดพลาดประวัติเสียงและลองใหม่อัตโนมัติ

## สิ่งที่เปลี่ยน / ไม่เปลี่ยน

- แยกสาเหตุและขั้นตอนที่ประวัติเสียงล้มเหลว แทนการบอกเพียงให้ตรวจพื้นที่และสิทธิ์
- เก็บตัวนับประกาศที่บันทึกสำเร็จแล้ว แม้รายการถัดไปในชุดเดียวกันบันทึกไม่สำเร็จ
- พยายามปิดฐานข้อมูลเสมอ แม้การบันทึกสถานะช่วงข้อมูลขาดล้มเหลว และไม่กลบข้อผิดพลาดเดิมด้วยข้อความว่าหยุดตามปกติ
- ชุดเสียงและเกณฑ์จับเสียงยังเป็นชุดเดียวกับ V43 (`field_camera_v41`): ไม่ลด threshold และไม่เปลี่ยนวิธีนับรอบ/จำนวนเงิน
- ไม่มีการล้างฐานข้อมูล เปลี่ยนกล้องเจ้าของข้อมูล ย้ายพาธเอง หรือลบทิ้งคิวเพื่อให้โปรแกรมเริ่มได้

## อ่านข้อผิดพลาดและการ recovery

หน้าจอแสดงเหตุ ขั้นตอน เช่น เปิดประวัติ/ยืนยันประวัติ/บันทึกช่วงขาด และเวลาที่จะลองใหม่

| รหัส | ความหมาย | พฤติกรรม |
|---|---|---|
| `storage_busy` | SQLite หรือไฟล์ถูกล็อกชั่วคราว | เว้นระยะ 2, 4, 8… สูงสุด 60 วินาทีต่อครั้ง |
| `storage_full` | พื้นที่ไม่พอจากรหัสระบบ | รออย่างน้อย 30 วินาที เพิ่มระยะสูงสุด 300 วินาทีต่อครั้ง |
| `storage_permission` | เขียนไม่ได้/อ่านได้อย่างเดียว/ถูกปฏิเสธ | รออย่างน้อย 30 วินาที เพิ่มระยะสูงสุด 300 วินาทีต่อครั้ง |
| `storage_io_error` | ระบบรายงานข้อผิดพลาด I/O | รออย่างน้อย 30 วินาที เพิ่มระยะสูงสุด 300 วินาทีต่อครั้ง |
| `storage_path_unsafe` | พาธไม่ผ่านเงื่อนไขป้องกัน link/root/hardlink | หยุด ไม่ข้ามการป้องกัน |
| `storage_camera_mismatch` | ฐานเดิมเป็นของกล้องอื่น | หยุด ไม่เปลี่ยนเจ้าของข้อมูล |
| `storage_schema` | โครงสร้างฐานข้อมูลไม่รองรับ | หยุด ไม่สร้างฐานใหม่ทับ |
| `storage_corrupt` | SQLite รายงานฐานข้อมูลเสียหรือไม่ใช่ฐานข้อมูล | หยุด ไม่ล้างหรือซ่อมแบบเดาสุ่ม |
| `storage_error` | ยังจำแนกสาเหตุไม่ได้ | หยุดพร้อมขั้นตอนที่ล้มเหลว ไม่วนเริ่มใหม่ไม่สิ้นสุด |

การลองใหม่ทำเฉพาะเมื่อเคยยินยอมฟังแล้ว ใช้การตั้งค่าและไฟล์โปรไฟล์เดิมที่ตรวจความตรงกันทุกครั้ง ไม่เปลี่ยนไปแหล่งอื่น การรอยังอยู่ภายใต้ปุ่ม **หยุดฟัง**; กดหยุด/ปิดโปรแกรมจะยกเลิกการลองใหม่ การเปลี่ยนการตั้งค่าหรือโปรไฟล์ต้องยินยอมเริ่มใหม่

รหัสที่ลองใหม่ได้หมายถึงสภาพแวดล้อม *อาจ* กลับมาพร้อม ไม่ได้แปลว่าโปรแกรมแก้พื้นที่/สิทธิ์/ฮาร์ดแวร์ให้เอง ต้องเปิดโปรแกรมและให้หน้าจอทำงานอยู่ ไม่ใช่บริการเบื้องหลังหลังปิดโปรแกรม

## เมื่อเสียงพร้อมเติมไม่ถูกนับ

ข้อมูลสุขภาพช่วยแยกสาเหตุ โดยไม่บันทึกไฟล์เสียง:

1. เฟรมเสียง/RMS: ยืนยันว่ารับข้อมูลมาแล้วหรือยัง RMS ศูนย์ที่วัดได้ไม่ใช่กรณีไม่มีข้อมูล และ RMS ไม่ใช่หลักฐานว่ามีคำพูดเป้าหมาย
2. สถานะสะสมเสียง: ต้องมีบริบทและรอช่วงยืนยันก่อน ไม่ปล่อยเหตุการณ์ก่อนเวลา
3. ผู้สมัคร/ปฏิเสธ/รอยืนยัน: เป็นข้อมูล **หน้าต่างวิเคราะห์ล่าสุด** ไม่ใช่จำนวนลูกค้า จำนวนรอบ หรือจำนวนธนบัตร; กำกวมเป็นยอดสะสมของช่วงรับเสียง
4. คะแนนพร้อมเติม raw เทียบเกณฑ์ และ temporal ณ ตำแหน่ง raw สูงสุด: ใช้ตรวจว่าตกขั้นตอนไหน ไม่ใช่เปอร์เซ็นต์ความน่าจะเป็น ค่าไม่ทราบจะไม่ถูกแสดงเป็นศูนย์
5. ลายนิ้วมือโปรไฟล์: ใช้เทียบว่ากำลังใช้ชุดเดียวกัน ไม่แสดง URL หรือ key
6. หากหน้าจอบอกว่ารอเสียงจบหลังช่วงขาด ระบบอาจจับประกาศได้แต่ยังไม่เปิดรอบใหม่ เพื่อไม่ผูกลูกค้าข้ามช่วงที่ไม่มีหลักฐาน

การ recovery ไม่ถือว่าข้อมูลช่วงที่หายเป็นความเงียบ ไม่สร้างเวลาจบหรือจำนวนเงินขึ้นเอง และไม่รับประกันกู้ประกาศที่ยังเขียนไม่ได้ลงดิสก์ โดยเฉพาะโปรแกรมปิด/ไฟดับขณะเขียนไม่ได้ คิวที่บันทึกแล้วไม่ถูกล้างจาก recovery; นโยบายหมดอายุเดิมยังคงอยู่

## นำไปใช้

หยุดรุ่นเก่าก่อน เปิด EXE V44 และตรวจว่าการตั้งค่า/โฟลเดอร์ข้อมูล/โปรไฟล์เป็นชุดที่ตั้งใจใช้ จากนั้นยินยอมเริ่มฟังตามเดิม ไม่จำเป็นต้องลบฐานข้อมูลเพื่ออัปเดต ไม่วาง prepared-profile รุ่นเก่าข้าง EXE ถ้าตั้งใจใช้ชุดที่ฝังอยู่

เมื่อพบปัญหา ให้เก็บภาพสถานะ รหัส ขั้นตอน และเวลาที่เกิด โดยไม่ส่ง URL/API key หากเป็นเสียงพร้อมเติมที่พลาดใหม่ ต้องมีคลิปช่วงก่อน–หลังเหตุการณ์จึงจะพิสูจน์สาเหตุด้านเสียงนั้นได้ การเพิ่ม diagnostics ไม่ใช่การยืนยันว่าแก้การพลาดทุกสภาพเสียงแล้ว
