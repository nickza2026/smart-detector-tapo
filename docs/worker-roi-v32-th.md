# .32 — วัตถุค้างในกรอบและmarkerจากภาพขนาดเก่า

ภาพ/เสียงยังใช้RTSPเหมือน .31 ไม่เพิ่มMEmu/ADB/Windowsloopbackกลับมา คู่มือเสียง/การยินยอม/startupเดิมดู `docs/rtsp-audio-v31-th.md`

## ใช้งาน

ปิด .31 ก่อนแล้วเปิด `SmartTapo.exe` .32 ใช้configเดิมตามปกติ ไม่ต้องรอให้มีแบงค์ค้างจริง ไม่ต้องส่งภาพเหตุขัดข้องเพื่อเปิดใช้ตัวตรวจ

ภาพอ้างอิงต้องเป็นภาพช่องว่างที่ผู้ใช้ยืนยันเอง และกรอบต้องครอบตำแหน่งที่วัตถุจะค้าง กรอบที่ผู้ใช้ยืนยันในภาพ1920×1080คือ X844/Y484/กว้าง223/สูง196 โปรแกรมไม่ได้เขียนเปลี่ยนกรอบ/ภาพอ้างอิง/คีย์/ฐานข้อมูลจริงในระหว่างพัฒนา ถ้าภาพอ้างอิงและกรอบปัจจุบันยังถูกต้องไม่ต้องทำใหม่เพียงเพราะอัปเดต .32

เมื่อเริ่มCapture/Worker ตัวตรวจเทียบเฉพาะกรอบกับภาพช่องว่าง ไม่ต้องรู้ว่าเป็นแบงค์:

- มีความต่างมากพอผ่านทั้งเกณฑ์ค่าเฉลี่ยและสัดส่วนพิกเซล → PRESENT เริ่มนับวัตถุ
- ครบจำนวนเฟรมและระยะเวลาต่อเนื่องตามค่าที่ตั้ง → วัตถุค้าง ค่าปัจจุบัน10ภาพที่1วินาทีมีช่วงอย่างน้อย9วินาที ไม่แจ้งตั้งแต่เจอความต่างครั้งแรก
- ผ่านแล้วออก/กลับเหมือนภาพช่องว่าง → EMPTY ล้างการนับตามเกณฑ์เคลียร์
- อ่านไม่ได้/จัดแนวไม่มั่นใจ/ภาพเก่าหรือไม่ผ่านprovenance → UNKNOWN ไม่ใช่ช่องว่าง ไม่เอาช่วงนั้นมาต่อให้ครบเกณฑ์

แสง เงา มือ และสิ่งแปลกปลอมอาจมีผลกับภาพ วิธีนี้เป็นตัวตรวจวัตถุค้าง ไม่ใช่ตัวจำแนกแบงค์หรือยืนยันยอดเงิน ไม่รับรองว่าความต่างเล็กทุกแบบจะตรวจได้

## บั๊กที่แก้

ตรวจmetadataในเครื่องแบบread-onlyพบmarker720×1280เก่า4ตัวปนเฟรมRTSP1920×1080 ขณะที่ภาพอ้างอิง/PNGจริงที่บันทึกแล้ว3ภาพอ่านได้เป็นEMPTY ค่าความต่างประมาณ0.21 จึงไม่ใช่เหตุให้บังคับเปลี่ยนROIหรือรอแบงค์จริง

Workerเดิมอ่านmarkerขนาดผิดแล้วรีเซ็ตการนับทุกครั้งที่scan ไฟล์เดิมที่ค้างจึงทำให้เฟรมใหม่ถูกต้องนับได้เพียง1ตลอด Regressionทำซ้ำได้ก่อนแก้

รุ่นนี้ปฏิเสธmarkerโดยไม่ลบภาพ/metadata/ประวัติจริง จดเวอร์ชันไฟล์ในcacheมีขอบเขต1024รายการและลายเซ็นชุดที่ปฏิเสธขนาดคงที่ จึงไม่รีเซ็ตจากชุดเดิมซ้ำเมื่อcacheเต็ม ถ้าไฟล์/ขนาดที่ตรวจเปลี่ยนต้องตรวจใหม่และเริ่มหลักฐานใหม่ ไม่ถือmarkerเสียเป็นเฟรมสำเร็จหรือช่องว่าง

ข้อความใหม่จะแยก “ปฏิเสธ marker” จากปัญหาอ่าน/วิเคราะห์ภาพ และระบุรหัสปลอดภัย `[observe/...]` เมื่อมีexception ไม่แสดงข้อความexceptionดิบ/path/URL/คีย์ ผู้ใช้ไม่ต้องลบไฟล์เก่าเองเพื่อให้เริ่มนับได้

## ขอบเขตที่ตรวจ

ทดสอบภาพผู้ใช้ที่ส่งมาโดยสังเคราะห์วัตถุในกรอบ/นอกกรอบ/แสง/กล้องขยับ/ภาพอ่านไม่ได้ และPNGที่บันทึกแล้ว ไม่ได้เชื่อมRTSPจริงหรือถอดรหัสคีย์ ไม่เปิดฐานข้อมูลลูกค้าจริง ไม่เขียนconfigจริง

Regressionใช้PNG→Detectorจริง→signedRTSPproof→Worker→SQLite/shadow ไม่ใช้bankclassifierstub ครอบคลุม10ภาพ/9วินาที,ผ่านแล้วออก,นอกกรอบ,UNKNOWN/stale/unhealthy,markerเปลี่ยน,1025badmarkers และauditข้อความปลอดภัย ColdGUIใช้ownedloopbackมีmarkerเก่า4ตัวค้างแต่ยังแจ้งshadowหลังหลักฐานครบ โดยเก็บmarkerไว้และไม่ลดTTL/threshold
