# .12 — เริ่มครั้งเดียว แล้วเฝ้า/พัก/กู้คืนเอง

รุ่นนี้แก้พฤติกรรมที่ตัวฟังหยุดแล้วต้องให้คนมากดเริ่มซ้ำ ไม่ต้องรอลูกค้าจริงเพื่อทดสอบขั้นพื้นฐาน

## ใช้ต่อจาก .11 โดยไม่ตั้งค่าใหม่

1. ปิดโปรแกรมเก่า วาง **SmartTapo.exe .12 แทนตัวเดิมในโฟลเดอร์เดิม** ไม่ลบconfig/data/prepared-profile ชุดZIPไม่มีไฟล์ตั้งค่าหรือข้อมูลผู้ใช้ที่จะเขียนทับ
2. เปิดโปรแกรม ใช้ปุ่ม **ใช้โปรไฟล์จากเสียงที่เตรียมให้** เช่นเดิม สำเนาเดิมจะถูกreuse ไม่ต้องเลือกWAV/กรอกเวลา/แก้JSON เลือกอุปกรณ์เสียงที่ต้องการเฝ้า
3. ยินยอม **เฝ้าจนกดหยุด รวมกู้คืนอุปกรณ์เดิม** แล้วกด **เริ่มฟังต่อเนื่อง** ครั้งเดียว หลังจากนั้นไม่ต้องคอยกดให้กลับมาฟังใหม่
4. **หยุดฟัง/ปิดโปรแกรม** ยกเลิกทั้งการรับเสียงและการกู้คืน คำสั่งที่กำลังทำจะถูกปิดและเก็บกวาดก่อนคืนการควบคุม ไม่เปิดรับเสียงเองเมื่อเปิดโปรแกรมรอบหน้า

## เมื่อไม่มีข้อมูลหรืออุปกรณ์สะดุด

- driverไม่มีแพ็กเก็ต: แสดง **ยังเฝ้าอยู่ — อุปกรณ์ยังไม่ส่งข้อมูลเสียง** ไม่อ่านแบบค้าง ไม่สร้างเสียงศูนย์ปลอม ไม่ถือว่าไม่มีคนเติม ยังต่ออายุการตรวจLiveและcleanupข้อมูลตามอายุ
- แพ็กเก็ตศูนย์ที่รับมาจริง: เป็นข้อมูลเงียบที่ประมวลผลได้ตามปกติ ต่างจากไม่ได้รับข้อมูล
- ช่วงเสียงขาดเกินขอบเขต: ทิ้งประโยคที่ค้างและเริ่มช่วงหลักฐานใหม่ ไม่ต่อครึ่งประโยคข้ามช่วงหาย ไม่ปลอมเวลาเสียงที่ไม่ได้รับ
- driver/process/ADBสะดุด: ปิดและรอเก็บกวาดงานเดิมก่อน ลองใหม่อัตโนมัติแบบเว้น1/2/5/10/30วินาที สูงสุดทุก30วินาที ไม่วนไม่จำกัดความถี่ ไม่เปิดหลายตัวพร้อมกัน
- ใช้อุปกรณ์รายการเดิมและโปรไฟล์hashเดิม ตรวจLiveใหม่ก่อนรับต่อ ไม่สลับไปไมโครโฟน/outputอื่น ไม่บังคับนำทางTapo และไม่ฟังPlaybackเป็นข้อมูลจริง การ reconnect ADBจำกัดเฉพาะloopbackserialเดิมที่ตั้งไว้ ไม่ถือว่าคำตอบconnectคือหลักฐานLive
- ถ้าชื่อ/ลำดับ/รูปแบบอุปกรณ์เปลี่ยนจนไม่ตรงกับรายการเดิม จะรออย่างเปิดเผย ไม่เดาตัวใหม่แทน การเปลี่ยนอุปกรณ์จริงให้กดหยุดเพื่อตั้งค่าใหม่ครั้งเดียว

## ประวัติช่วงที่ขาดต้องไม่ปนลูกค้าคนถัดไป

ถ้าเสียงขาดขณะมีรอบเปิดอยู่ รอบนั้นเป็น **หลักฐานเสียงขาดช่วง / ไม่ทราบเวลาจบ** (`interrupted`, `ended_at=null`) ไม่สมมติว่าลูกค้าเติมจบ ไม่คำนวณยอดเงินและไม่สร้างคำกล่าวว่าไม่มีเสียงจบครบ5นาทีจากช่วงที่รับข้อมูลไม่ได้

เสียงพร้อมเติมที่ได้ยินหลังgapยังเก็บเป็นหลักฐาน แต่ไม่เอาไปรวมรอบเดิม/แต่งรอบลูกค้าใหม่จนได้ยินประกาศสิ้นสุดจริงเพื่อยืนยันขอบเขต จากนั้นพร้อมเติมครั้งถัดไปเปิดรอบใหม่ ส่วนรอบเก่ายังคงไม่ทราบเวลาจบ ถ้าgapเกิดตอนที่ไม่มีรอบเปิด ไม่มีการสร้างรายการเติมปลอมเพื่อบันทึกความเงียบ

ข้อมูลและรูปยังมีอายุ72ชั่วโมง ปัญหาที่เคยยืนยันก่อนgapไม่ถูกลบทิ้ง การพัก/กู้คืนไม่ขยายอายุรอบ

## หลักฐานและข้อจำกัด

ทดสอบvirtualหนึ่งชั่วโมงไม่มีแพ็กเก็ต/กลับมามีข้อมูล, retry60รอบ, หยุดระหว่างพัก/SDKค้าง และUIStartครั้งเดียวกับprocessแยก3ครั้ง+SQLiteจริงในโฟลเดอร์ทดสอบ ได้รอบinterruptedหนึ่งรอบและcompletedสองรอบที่ไม่ถูกผูกรวม ไม่ต้องใช้ลูกค้าหรืออุปกรณ์จริงในการตรวจเส้นทางเหล่านี้

นี่ไม่ใช่การรับรองความแม่นยำของเสียงทุกแบบหรือทุกสภาพVPS สาเหตุย่อยของภาพstream_faultเดิมยังไม่ได้พิสูจน์บนVPS; รุ่นนี้แก้การรอข้อมูล/การกู้คืนและเปิดเผยรหัส/เวลาที่ขัดข้อง แทนการให้คนคอยเริ่มใหม่หรือปิดguardทิ้ง

**Remote Audio ผูกกับระบบเสียงของRDP:** หากการออกRDPทำให้Windowsหยุดส่งหรือถอดอุปกรณ์ โปรแกรมจะรอ/ลองกู้ ไม่สามารถสร้างเสียงแทนWindowsได้ การเฝ้าขณะออกRDPจริงต้องใช้outputที่ยังคงทำงาน เช่นvirtualoutputถาวรที่MEmuส่งเสียงเข้าจริง ชุดนี้ไม่ได้ติดตั้งdriver/เปลี่ยนWindowsหรือสลับoutputให้อย่างเงียบ ๆ

เสียงWindowsยังเป็นแบบผสม ห้ามเปิดคลิปต้นแบบ/ประกาศจากแอปอื่นบนoutputเดียวกันขณะเฝ้า ยังไม่ผูกรูปก่อนประกาศหรือส่งdashboardอัตโนมัติ ชุดเสียงในZIPเป็นข้อมูลส่วนตัวที่คุณให้ ไม่เผยแพร่GitHubหรือส่งบริการถอดเสียง
