# SmartTapo .15 — candidate สำหรับกู้คำถามดู Live ต่อครบ 5 นาที

รุ่น `2026-10-30.15` ผ่าน regression ในเครื่อง แต่ **ยังไม่ผ่านการทดสอบจริงข้ามป๊อปอัป 5 นาทีหลังแก้ล่าสุด** การทดสอบเสียงถูกหยุดก่อนเริ่มรอบยาว เพราะพบ Windows Default Output เปลี่ยนมาเป็น CABLE Input จึงไม่ควรนำรุ่นนี้ขึ้นเฝ้าจริงแทนการทดสอบ

## ชุดไฟล์และการรักษาข้อมูล

ชุดส่งมอบแบบ candidate อยู่บนเครื่องหลัก ไม่ได้ส่งหรือรันบน VPS อัตโนมัติ:

```text
D:\works\smart-detector-tapo\.tools\SmartTapo-v15-inactivity-candidate.zip
```

เมื่อผ่านการยืนยันจริงแล้วจึงค่อยอัปเดต: หยุด Capture/Worker/เสียง ปิด EXE เก่า แทนเฉพาะ EXE ในโฟลเดอร์เดิม ใช้บัญชี Windows เดิม ไม่ลบ `config.local.json`, data, ภาพช่องว่าง, โปรไฟล์ หรือประวัติ ไม่เปิดสองรุ่นซ้อนกัน ชุด prepared-profile เหมือนรุ่นก่อน ไม่ต้องสร้างเสียงตัวอย่างใหม่

## การกู้คำถาม 5 นาที

- รองรับเฉพาะป๊อปอัปภาษาไทยที่เก็บหลักฐานจริงแล้ว: ข้อความดู Live ครบ 5 นาที ปุ่ม **ต่อไป / ยกเลิก / ปิด** และ activity ตรงตามที่ตรวจไว้ ไม่เดาจากคำว่า “ต่อไป” เพียงอย่างเดียว
- ป๊อปอัปบังชื่อกล้องและปุ่ม Live จึง **ไม่ถือว่าป๊อปอัปคือหลักฐาน Live** ต้องเคยอ่านชื่อกล้องที่ตั้งไว้และชุดปุ่ม Live ครบจริงใน session เดียวกันล่าสุด ภายในอายุ proof เดิม ไม่ขยาย TTL
- หากเปิดโปรแกรมมาเจอป๊อปอัปเลย โดยยังไม่เคยยืนยันชื่อกล้อง จะไม่กดต่อให้อัตโนมัติ ต้องเปิด Live กล้องที่ถูกต้องก่อน
- ตรวจหน้าจอซ้ำหลังรอ decision lock ไม่ใช้พิกัดปุ่มเก่าหากป๊อปอัปหาย ย้ายตำแหน่ง หรือเปลี่ยนหน้า กดต่อได้ไม่เกินหนึ่งครั้งต่อสิทธิ์ แล้วต้องอ่านชื่อกล้องและชุดปุ่ม Live ใหม่ก่อนใช้ภาพ/เสียง
- การหยุดงานหรือหลักฐานหมดอายุ/เปลี่ยนกล้อง/เปลี่ยน generation ต้องไม่กดต่อ ไม่กด Talk, Alarm, Privacy, Light, Back, Home หรือ login เพื่อเดาทางกลับ
- หลังมี navigation ช่วงเสียงเก่าต้องจบ epoch และพักอย่างปลอดภัย Watch จึงเริ่มตรวจและฟังรอบใหม่ ไม่ต่อคำพูดข้ามช่วงขาด ไม่สร้างเหตุการณ์จบการเติมปลอม

## กรอบนาฬิกาที่ตรวจจริงบนเครื่องหลัก

ADB ของเครื่องหลักให้ภาพ `720×1280` และพื้นที่วิดีโอ `[0,176][720,581]` ภาพจริงสามภาพพบว่ากรอบเริ่มต้น `(0,132,280,21)` อยู่บนส่วนหัวและไม่เปลี่ยน ส่วน `(0,176,280,24)` ครอบเวลาวิดีโอและเปลี่ยนทั้งสองคู่ที่เปรียบเทียบ

นี่คือหลักฐาน **ของ layout เครื่องหลักที่ตรวจครั้งนี้** ไม่ใช่คำสั่งเปลี่ยน default ทุกเครื่องหรือการยืนยันค่า VPS:

1. หยุดงานทั้งหมด เปิด Live กล้องเดิม แล้วกด **ดูภาพอุปกรณ์ ADB (ไม่บันทึก)**
2. ดูกรอบสีฟ้าและภาพขยายนาฬิกา ต้องเป็นตัวเลขเวลาในวิดีโอ ไม่ใช่หัว Tapo/นาฬิกา Android/พื้นที่เคลื่อนไหว
3. ลากครอบเวลา ติ๊กยืนยัน แล้วกด **บันทึกเฉพาะกรอบนาฬิกา** ไม่ต้องแก้ JSON การเปิดภาพหรือแค่ลากยังไม่บันทึก
4. การบันทึกนี้ไม่เปลี่ยนกรอบแบงก์หรือ baseline และไม่พิสูจน์ Live ด้วยตัวเอง หากเปลี่ยนกล้องหรือฟอร์มให้เปิด preview ใหม่

กรอบแบงก์ `249,272,100,80` จากคลิปเดิมยังเป็นเพียง preview ต้องตรวจตำแหน่งจริงและยืนยันภาพช่องว่าง ไม่ถือว่าภาพล่าสุดที่อ่านได้ว่างโดยอัตโนมัติ

## เสียงเครื่องหลักต้องแยกจากงานอื่น

- ตั้ง output **ของ MEmu เท่านั้น** เป็น `CABLE Input (VB-Audio Virtual Cable)` แล้วเลือกตัวรับ `CABLE Input ... [Loopback]` ตัวปกติให้ตรงกัน ไม่สลับเป็น 16ch หรือไมค์ Windows เอง
- เสียงหลัก Windows และ Communications ต้องยังเป็นลำโพง/หูฟังที่ใช้งาน ไม่ใช่ CABLE หาก Windows สลับ Default มา CABLE อาจมีเพลง/เสียงงานปนเข้าตัวรับได้ ต้องหยุดการทดสอบก่อน ไม่เปิดฟังต่อโดยถือว่าเป็น MEmu ล้วน
- ชุดทดสอบไม่ได้ออกคำสั่งเปลี่ยน Default/volume/mute และไม่ได้เปิดไมค์เครื่องหลัก ไม่ได้เล่นเสียงทดสอบหรือเขียน PCM/WAV จริง แต่สาเหตุที่ Windows สลับ Default ยังไม่ยืนยัน จึงไม่อ้างว่าการแยกแหล่งเสียงคงเดิมตลอดช่วงก่อนพบการเปลี่ยน
- ไม่เพิ่มเกณฑ์ `audio_clock_discontinuity` จาก 2 วินาทีเพื่อกลบอาการ ค่า lag ไม่ได้พิสูจน์ว่า CPU ช้าเสมอไป ต้องดูจำนวน PCM, ช่วงไม่มี packet, backlog, read/work/lock/commit ประกอบ

## สิ่งที่ตรวจได้แล้วและที่ยังไม่ผ่าน

- MEmu อยู่นอกขอบทุกจอ ไม่ minimize และการย้าย/ADB tap ที่ทดสอบไม่เปลี่ยน foreground เดิม
- Capture เดี่ยว 20 วินาทีได้ 21 ภาพ 20 ภาพ fresh รอบปกติประมาณ 0.19–0.24 วินาที ไม่มี missed slot หลังเริ่มงานในรอบนั้น
- CABLE เดี่ยว 30 วินาทีได้ PCM 29.98 วินาที ไม่มี overflow และ backlog สูงสุด 0.02 วินาที
- Capture คู่ตัวฟังจริงเคยเกิด `audio_clock_discontinuity` ที่ lag 2.01 วินาที จึงยังไม่ยืนยันว่าใช้งานคู่กันต่อเนื่องได้
- ตัวฟังเดี่ยวรอบหนึ่งจบครบ 120 วินาที แต่ frame counter มีการเริ่ม epoch ใหม่ ไม่ใช่หลักฐานว่าไม่มีเสียงขาดหรือฟังประกาศครบทุกคำ รอบอื่นพบ fresh UI ล้มชั่วคราวด้วย
- Regression 437 tests: ผ่าน 436 / ข้าม 1 ตาม contract คนละระบบปฏิบัติการ รวม fixture ป๊อปอัปจริงและกรณี UI เปลี่ยนระหว่างรอ lock ผล frozen EXE/เลข hash ตรวจจาก receipt ของชุดที่สร้างจริง ไม่ใช้การ compile แทนผลทดสอบ

**ยังไม่ยืนยัน:** การกู้ป๊อปอัปจริงด้วยโค้ดใหม่ข้าม 5 นาที, Capture+Watch ระยะยาว, VPS หลังปิด VNC/RDP, ความแม่นยำ Worker บนภาพจริง/ภาพช่องว่างปัจจุบัน, ประกาศจริงครบวงจร และ Pushover/โทรศัพท์ ไม่มีการใช้เงินจริง สั่งตู้ หรือเชื่อมผู้ให้บริการแจ้งเตือนจริง

ยังคง strict 10 ภาพและ gap เดิม ข้อเสนอขาดหนึ่งลำดับ/ไม่เกิน 3 วินาทียังรอคำยืนยัน ไม่ติดตั้ง Task Scheduler/service/auto-logon ไม่ต่อ webhook ใหม่ และไม่มี commit/push
