# อัปเดตจาก GitHub สาธารณะ

## แพตช์ตัวบล็อก V50

ประวัติ `interrupted` เก็บตามจริงโดยไม่มีเวลาจบที่ยืนยัน การมีประวัติเก่าแบบนี้ไม่ใช่หลักฐานว่าขณะนี้ยังมีการเติม V50 ตรวจ checkpoint และสถานะรอขอบเขตใน read-only transaction เดียวกัน หากมี End ที่รับจริงหลังการขาดช่วงล่าสุดและไม่มีงาน/รอบปัจจุบันค้าง จะไม่ใช้ประวัติเก่าบล็อกการติดตั้ง ไม่เติมเวลาจบ ไม่เปลี่ยนสถานะประวัติเก่า และไม่ลบฐานข้อมูลหรือคิว

รอบเปิดอยู่ สถานะรอ End หลังเสียงขาด/หมดอายุ ไม่มี End ที่ยืนยันหลังการขาดช่วงล่าสุด หรือข้อมูลอ่าน/ตรวจสอบไม่ได้ยังบล็อกตามเดิม End เก่าก่อนการขาดช่วงใหม่ไม่ปลดล็อก และการหยุด process หรือเวลาผ่านไปอย่างเดียวไม่ใช่ End

ตัวบล็อกทำงานใน EXE ที่เปิดอยู่ การดาวน์โหลดรุ่นใหม่ไม่เปลี่ยนโค้ดในตัวเก่า หากตัวเก่าติดบั๊กนี้ การเปลี่ยนด้วยตนเองทำได้หลังผู้ใช้ยืนยันว่าตู้ไม่มีการเติมจริง หยุดทุกงานและปิดโปรแกรมเก่า เก็บ EXE เก่าสำรอง แล้วแทนเฉพาะ EXE ในโฟลเดอร์เดิมและคงชื่อที่ shortcut/startup อ้าง ไม่ย้าย/ลบ config, profile, history, outbox, DB/WAL/SHM การเปลี่ยน EXE ไม่ล้างสถานะรอบขาดช่วง

รุ่นสาธารณะที่ตรวจยืนยันล่าสุดก่อนแพตช์นี้คือ V49; V50 ต้องผ่านการตรวจและได้รับอนุญาตเผยแพร่แยกต่างหาก หลักฐานทดสอบ native engine รุ่นเก่าด้านล่างไม่ใช่หลักฐานติดตั้ง V50 บน VPS จริง

แท็บ **อัปเดตโปรแกรม** ตรวจสอบ Releases เมื่อเปิดโปรแกรมปกติ แล้วตรวจซ้ำทุก 6 ชั่วโมงขณะเปิดค้าง และกดตรวจสอบเองได้ จำกัดอย่างน้อยหนึ่งชั่วโมงต่อการตรวจสอบ รวมเมื่อเกิดข้อผิดพลาด ไม่ดาวน์โหลด ปิดโปรแกรม หรือเปิดกล้อง/API อัตโนมัติ โหมด smoke ไม่ตรวจเครือข่าย ปิดโปรแกรมจะยกเลิก timer

**ระบบลงลายเซ็น:** ผู้ดูแลอนุญาตสร้างกุญแจลงนามวันที่ 8 พฤศจิกายน 2569 และสร้างแบบ Windows current-user DPAPI นอก repo แล้ว โปรแกรมฝังเฉพาะกุญแจสาธารณะ SHA256 `48c5bea4bfc1e61a63b56ddb4ac5c865ca6033a49b686ee7f05f5bb127d8f98a` มี Windows helper, transaction journal, rollback และ readiness handshake เชื่อมกับหน้าต่างปกติ โดยตรวจรุ่นที่คอมไพล์จริงและลายเซ็นก่อน ACK ไม่หยุดงานหรือรอบเติมเอง และตัว engine ไม่แก้การตั้งค่า โปรไฟล์ ประวัติ outbox หรือฐานข้อมูล การอนุญาตเผยแพร่แต่ละรุ่นไม่อนุญาตสร้างกุญแจใหม่หรือเผยแพร่รุ่นถัดไปอัตโนมัติ

ทดสอบ native engine → หน้าต่างปกติแล้วด้วย EXE onefile รุ่นทดสอบแยก V45/V46 และกุญแจทดสอบชั่วคราวเท่านั้น: อัปเกรดสำเร็จ, รุ่นใหม่ออกก่อน ACK แล้วย้อนกลับ, และ timeout ไม่ส่ง ACK แล้วย้อนกลับ หน้าต่างจริงแสดงนอกทุกจอโดยไม่แย่ง focus ไม่ใช่การติดตั้งกับข้อมูลจริงหรือการยอมรับ production และไม่ได้ทดสอบเส้นทางคลิกปุ่มครบวงจร หลักฐาน: `.tools/v45-native-310e7b33c18947d187405f6b76699a5b/native-acceptance.json`

เครื่องที่ใช้ V44 ต้องเปลี่ยน EXE เป็นรุ่นที่มี updater และ public key ที่อนุมัติด้วยตนเองหนึ่งครั้งก่อน รุ่นเดิมไม่สามารถเพิ่ม updater ให้ตัวเองจากระยะไกลได้

หากรุ่นใหม่ยังไม่เซ็นหรือไม่มี key ที่ pin ไว้ จะแจ้งเหตุผลและไม่ยอมรับไฟล์เพื่อการติดตั้ง ไม่มี hash-only fallback ปุ่มรายละเอียดเปิดหน้า Releases สาธารณะหลังยืนยัน ไม่ถือว่าการดาวน์โหลดเองปลอดภัยเทียบเท่าการตรวจลายเซ็น

รูปแบบที่วางแผนไว้: tag `V45` (ตัวพิมพ์ใหญ่ V ตามด้วยจำนวนเต็มเพิ่มขึ้น), asset `SmartTapo-V45.exe` และ `SmartTapo-update.json` มี repository, version, ชื่อ EXE, size, SHA256 และลายเซ็น Ed25519 ตาม schema ใน `smart_tapo/updates.py` ลายเซ็นครอบคลุม JSON UTF-8/ASCII ที่เรียง key และไม่มี whitespace ยกเว้น field signature

กุญแจสาธารณะในรุ่น bootstrap มาจากการสร้างบนเครื่องโดยตรง ไม่รับกุญแจจาก release ที่ยังตรวจไม่ได้ รวม cryptography ที่ pin แล้วใน build ห้ามปล่อย private key ใน source, source ZIP หรือ EXE กุญแจส่วนตัว DPAPI ผูกกับบัญชี Windows: ไฟล์อย่างเดียวอาจกู้คืนไม่ได้หลังสูญเสียบัญชีหรือลง Windows ใหม่ ยังไม่ได้สำรองหรือ export และต้องวางแผนสำรองอย่างปลอดภัยแยกต่างหาก การเผยแพร่ release ยังต้องขออนุญาตแยกต่างหาก
