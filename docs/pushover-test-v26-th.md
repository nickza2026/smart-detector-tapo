# SmartTapo .26 — ปุ่มทดสอบส่ง Pushover จริง

## วิธีใช้

1. ปิดSmartTapoตัวเดิม เปิด`.tools/diagnostic-v26/SmartTapo.exe`
2. แท็บ**1. ตั้งค่า** เลื่อนถึง**Pushover** ตรวจApp TokenและUser/Group Keyในช่องที่ปิดบังอยู่ แอปโหลดค่าที่บันทึกเดิมให้เหมือนก่อน หรือใช้ค่าที่กรอกปัจจุบันได้โดยไม่ต้องเปิดแจ้งเตือนอัตโนมัติ
3. กด**ทดสอบส่ง Pushover จริง** อยู่ข้างปุ่มบันทึก/ล้างคีย์/เปิดโฟลเดอร์ข้อมูล แล้วอ่านและยืนยันข้อความว่าจะส่งจริงหนึ่งครั้งไปยังบัญชีตามค่าที่กรอกอยู่ หากกดยกเลิกหรือกรอกไม่ครบจะไม่ส่ง
4. ระหว่างส่งปุ่มถูกปิด ไม่กดค้างเพื่อส่งซ้ำ รอผลใต้ปุ่มก่อน ไม่ต้องหยุดCapture/Workerและไม่ต้องเปิดMEmu/เสียงเพื่อทดสอบช่องทางแจ้งเตือน

ไม่ต้องส่งคีย์ในแชต ตัวส่งใช้snapshotค่าตอนกด ไม่อ่านคีย์ใหม่ระหว่างคำขอ ไม่เปลี่ยนหรือบันทึกคีย์/env/configเอง ไม่เปลี่ยนบัญชีผู้รับโดยอัตโนมัติ

## อ่านผลให้ถูก

- **Pushoverยืนยันรับคำขอแล้ว:** providerตอบstatus1 ไม่ใช่การยืนยันว่ามือถือดัง/แสดงข้อความ/ผู้ใช้รับทราบ ต้องตรวจที่โทรศัพท์เอง
- **ไม่ได้รับการยืนยันการรับคำขอ:** ไม่ได้ผลยืนยันจากprovider ไม่เอาresponsebodyหรือคีย์มาแสดงในUI/log
- **อาจส่งแล้วแต่หมดเวลารอ:** ผลไม่แน่ชัด **ตรวจโทรศัพท์ก่อนกดอีกครั้ง** โปรแกรมไม่ส่งซ้ำอัตโนมัติ เพราะคำขอก่อนอาจส่งถึงแล้ว
- ปิดแอประหว่างคำขอที่เริ่มแล้ว: รอเก็บผลก่อนออก ข้อความที่ส่งไปแล้วเรียกคืนไม่ได้ ถ้ายังไม่เริ่มจึงยกเลิกได้ ไม่อ้างว่าปิดแอปแปลว่าโทรศัพท์จะไม่ได้รับข้อความ

เป็นข้อความหัวข้อ**SmartTapo TEST** เนื้อหาระบุว่าไม่ใช่เหตุการณ์กล้องจริง ใช้priority1เหมือนfallbackเดิม ไม่ใช่emergencypriority2 ไม่มีreceipt/persistentalarm/Acktracking เสียงและการแสดงผลขึ้นกับการตั้งค่าPushover/ระบบโทรศัพท์

## แยกจากการทำงานอัตโนมัติ

Checkbox**เปิดแจ้งเตือนอัตโนมัติจาก Worker**ควบคุมWorkerเหมือนเดิม ไม่ใช่สวิตช์ห้ามปุ่มทดสอบแยก: ปิดcheckboxแล้วยังกดยืนยันส่งTESTจริงได้ แต่การกดTESTไม่เปิดcheckbox/เปลี่ยนnotify_enabled/สร้างรายการเติม/job/outbox/history/เหตุการณ์กล้อง ไม่เปิดAPIqueueหรือฟังเสียง ไม่เริ่มCapture/Worker ไม่หยุดงานที่กำลังเฝ้าอยู่ ไม่มีscheduledtestหรือretryหลังเปิดแอปใหม่

ปลายทางเป็นHTTPS PushovermessagesAPIคงที่ ไม่followredirectหรือเปลี่ยนglobalnetworksettings มีsockettimeout10s/จำกัดresponse ไม่เก็บrawproviderbody/errorหรือคีย์ในstatus ตัวเลือกเครือข่ายพื้นฐานยังเป็นของระบบเหมือนurllibเดิม

## ขอบเขตตรวจสอบ

ระหว่างพัฒนาตรวจด้วยHTTPfakeและoffscreenGUIเท่านั้น ไม่มีการส่งไปบัญชีจริงหรืออ่านคีย์จริง ผลfake/source/frozenไม่ใช่หลักฐานว่าโทรศัพท์ผู้ใช้รับข้อความแล้ว ผู้ใช้ต้องกดยืนยันปุ่มจริงเองหนึ่งครั้งเพื่อทดสอบช่องทางของตน
