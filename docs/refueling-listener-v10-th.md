# Diagnostic .10 — ฟังประกาศเติมต่อเนื่องแบบทดลอง

**ถ้าใช้ .11:** กด **ใช้โปรไฟล์จากเสียงที่เตรียมให้** ได้เลย ไม่ต้องทำหัวข้อเลือกWAV/กรอกเวลาเองด้านล่าง หัวข้อนั้นเป็นวิธีตั้งเองขั้นสูงของรุ่นเก่าเท่านั้น

ชุด Live/Playback ใหม่จาก .9 แยกกันจริง: อุปกรณ์เดียวกัน อ่านไฟล์ใหม่คนละคำขอ Live มี75nodes ส่วนPlaybackมี40nodesและแถบเวลา จึงเพิ่มตัวตรวจหน้าแบบรู้จักโครงสร้าง ไม่ใช้ชื่อไฟล์/ป้ายที่คนเลือก ไม่ถือปุ่มเข้าPlaybackหรือlive_surface_viewอย่างเดียวเป็นหลักฐานLive

## สิ่งที่ใช้ได้และขอบเขต

- เปิดแอป/แท็บไม่เริ่มเสียง ไม่ค้นอุปกรณ์ ไม่เริ่มSDKหรือสร้างประวัติสาธิตในข้อมูลจริง ต้องเลือกอุปกรณ์/โปรไฟล์และยินยอมแต่ละรอบ แล้วกดเริ่มเอง
- รับเฉพาะWindows WASAPI output-loopbackที่เลือก ไม่เปลี่ยนอุปกรณ์หรือใช้ไมค์สำรอง ไม่เก็บWAVของการฟังต่อเนื่องหรือส่งเสียงออกเครือข่าย
- ตรวจหน้าLiveของกล้องที่ตั้งไว้ก่อนรับเสียงและตรวจซ้ำ หน้าPlayback/unknown/ตรวจไม่สำเร็จ/หลักฐานหมดอายุ/เสียงขาดช่วงจะหยุด ต้องเริ่มใหม่เอง ไม่เล่นหรือสลับหน้าTapoให้
- ประกาศพร้อมเติมที่ยืนยันครั้งแรกเปิดรอบ ประกาศพร้อมซ้ำอยู่รอบเดิมพร้อมissueและเริ่มนับ5นาทีจากพร้อมล่าสุดใหม่ จบเมื่อยืนยันวลีขอบคุณ/สิ้นสุดเท่านั้น หยุดฟัง/เงียบ/driverล้ม/เวลาเกินไม่กรอกเวลาจบปลอม
- เวลาเป็นเวลาที่ตัวรับเห็นเสียง ไม่ใช่หลักฐานเวลาหยอดจริง/ยอดรับเงินจริง ไม่มีจำนวนเหรียญหรือยอดเงินที่อนุมานจากความดัง
- เก็บประวัติใหม่/checkpoint/คิวส่งในเครื่อง ดูที่แท็บ **ประวัติการเติม** กู้รอบเดิมหลังเปิดใหม่ได้ ข้อมูลประวัติใหม่/รูปของระบบเติมมีอายุ3วัน การเก็บแบบเก่าของWorkerภาพไม่ได้เปลี่ยนตามส่วนนี้
- **ยังไม่เชื่อมรูปก่อนประกาศหรือส่งdashboardอัตโนมัติ** โดยตัวฟังนี้ ไม่เดาว่ารูปไหนเป็นลูกค้าคนไหน APIv1และclientที่ทดสอบแยกไว้ยังอยู่ ต้องตรวจการเชื่อมภาพ/ปลายทางจริงต่อก่อนถือว่าครบทั้งระบบ

## ข้อจำกัดที่ต้องยอมรับก่อนทดสอบ

Windows loopbackรวมเสียงทุกแอปที่ใช้เสียงขาออกเดียวกัน แม้ตรวจว่าTapoอยู่Liveก็ **ไม่ได้พิสูจน์ว่าเสียงมาจากTapoเพียงแอปเดียว** ห้ามเปิดคลิปประกาศ/WAVต้นแบบจากโปรแกรมอื่นขณะฟัง เพราะอาจถูกนับเป็นประกาศจริงได้ การตรวจหน้าตามช่วงเวลาอาจไม่เห็นการสลับไปกลับระหว่างช่วงตรวจ จึงยังไม่ใช่ระบบรับรองเงินหรือการทดสอบproduction

Correlationเป็นคะแนนความเหมือน ไม่ใช่โอกาสถูกต้อง Templateที่โหลดผ่านไม่ได้แปลว่าวัดความแม่นยำแล้ว ถ้าสองชนิดตรงกันซ้อนช่วงจะไม่เลือกผู้ชนะเอง ไม่สร้างรายการจากเสียงกำกวม ต้องทดสอบกับเสียงอิสระ/เสียงรบกวนจริงก่อนใช้ตัดสินงาน

## เตรียมโปรไฟล์ส่วนตัวผ่านUI

1. ปิดรุ่นเก่า เปิด.10 บันทึกการตั้งค่ากล้องให้ถูก หยุดCapture/Worker/เสียงก่อนตั้งค่า
2. แท็บ **เสียง MEmu / ฟังเติม** → แท็บย่อย **ฟังประวัติเติมต่อเนื่อง (ทดลอง)** → **สร้างโปรไฟล์จาก WAV ของฉัน…**
3. เลือกWAV PCM16ปกติสองไฟล์ของคุณ: วลี **พร้อมเติม** และ **ขอบคุณ/สิ้นสุด** ไม่ใช้เสียงเคาะหรือบี๊ปแทนประโยค ไม่ใช้ไฟล์สังเคราะห์ในหลักฐานทดสอบเป็นเสียงจริง
4. ระบุจุดเริ่ม/จบของ **ประโยคเต็ม** ด้วยตนเอง ช่วงยาว0.8–9.5วินาที ถ้าประโยคยาวเกินนี้ห้ามตัดทิ้งเพื่อให้ผ่าน ค่าเกณฑ์0.9ที่แสดงเป็นค่าเริ่มทดลอง ไม่ใช่90%และไม่ใช่ค่าที่ปรับกับกล้องคุณแล้ว
5. ทบทวนช่วง/ชนิด กดยืนยัน แล้วสร้างโปรไฟล์ งานตรวจ/คัดลอกอยู่เบื้องหลัง ไม่เริ่มเสียง ปิดหน้าสร้างไม่ได้ระหว่างเขียนเพื่อไม่ทิ้งไฟล์ครึ่งสำเร็จ เมื่อเสร็จจะเติมช่องJSONให้เอง

ต้นฉบับไม่แก้ไข/ไม่ลบ สำเนาต้นแบบและJSONเป็นการตั้งค่าถาวรในโฟลเดอร์announcement-profilesของข้อมูลที่ตั้งไว้ ไม่อยู่ในประวัติ3วัน ไม่อัปโหลด ลบเองได้เมื่อหยุดใช้งานโปรไฟล์นั้น เก็บบนโฟลเดอร์จริงไม่ใช้junction/symlink/shortcutหรือไฟล์ที่แก้ผ่านhardlink

## เริ่ม/หยุดและดูผล

1. เปิดTapoหน้าLiveแนวตั้ง ให้ชื่อกล้องและแผงควบคุมมองเห็น เปิดลำโพงในTapo ไม่ใช่ไมค์/ปุ่มพูดคุย ใช้ **ดูภาพอุปกรณ์ ADB** ตรวจว่าSerialตรงMEmuที่ดูอยู่ก่อน
2. ถ้าจะใช้Capture/Workerภาพแบบเดิมด้วย ให้เริ่มก่อนตัวฟัง ไม่เริ่ม/เปลี่ยนconfig/ถ่ายภาพcalibrationระหว่างฟัง แต่หยุดทั้งหมดได้เสมอ
3. ที่แท็บย่อย **ทดสอบ10วินาที / เลือกอุปกรณ์** กดรีเฟรชและเลือกoutputที่MEmuใช้ ทดสอบระดับเสียงแล้วรอจบก่อน รอบฟังต่อเนื่องไม่ใช่ปุ่มบันทึกWAV10วินาที
4. กลับแท็บย่อยฟังต่อเนื่อง เลือกJSONที่สร้างไว้ ยินยอมรอบนี้ กดเริ่ม ช่วงเตรียมกำลังตรวจโปรไฟล์/Live ยังไม่ถือว่าเปิดรับเสียงสำเร็จ ต้องมีตัวอย่างเสียงจริงก่อนสถานะรับเสียง
5. ดูรายการที่แท็บ **ประวัติการเติม** มีlookaheadเพื่อรอวลีเต็ม/กันสองชนิดชนกัน จึงอาจช้าตามความยาววลีและเครื่อง ไม่กรอกเวลาจบจากเวลารอ ตัวนับประกาศในหน้าเสียงไม่ใช่จำนวนการจ่ายค่าน้ำมัน
6. กด **หยุดฟัง** หรือ **หยุดทั้งหมด** รอปิดตัวรับ/บันทึกข้อมูลจนเสร็จ ไม่ถือว่าเติมจบ หากบังคับหยุด/timeoutอาจขาดข้อมูล แต่ประวัติที่commitแล้วอยู่ต่อ

หากไม่พบอุปกรณ์/เสียงหายหลังออกRDP/Liveตรวจไม่ผ่าน ไม่ใช่ข้อสรุปว่าไม่มีการเติม ไม่สลับdriver/เปิดอุปกรณ์อื่นให้อัตโนมัติ รองรับรูปแบบทั่วไป44.1/48kHz stereoและมีขอบเขตRAM16MiB/หน้าต่าง20วินาที รูปแบบใหญ่หรือไม่รองรับจะปฏิเสธก่อนเปิดเสียง

## สถานะการยืนยัน

แยก **รายงานหน้าจอจริงของผู้ใช้** ออกจาก **การทดสอบเสียงสังเคราะห์/tempSQLite/spawn/GUIนอกจอ** ไม่มีการเปิดเสียง/ADB/DBผู้ใช้หรือเชื่อมdashboardจริงจากเครื่องพัฒนา ยังไม่มีผลความแม่นยำของวลีจากMEmuจริง/การทำงานหลังdisconnectRDP/การผูกรูปก่อนพร้อม/ส่งปลายทางจริง จึงใช้ทดสอบแบบมีผู้ดูแลก่อน ไม่ประกาศproduction-ready
