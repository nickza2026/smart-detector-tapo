# ประวัติประกาศเริ่มหรือจบที่ยังจับคู่เป็นรอบไม่ได้

การแก้ในซอร์สนี้ยังไม่ได้เผยแพร่เป็น EXE รุ่นใหม่ เหตุเดิมคือประกาศที่ยืนยันแล้วถูกเก็บใน `observations` แต่หน้าประวัติอ่านเฉพาะรอบใน `sessions` จึงไม่เห็นเสียงจบเดี่ยวหรือเสียงพร้อมเติมที่ถูกกันไว้หลังช่วงขาด

ตารางประวัติเดิมแสดงทั้งรอบเติมและประกาศที่ยังไม่ได้ถูกรวมไว้ในรอบ:

- เสียงพร้อมเติมที่เปิดรอบตามปกติแสดงรอบที่ยังไม่จบ เมื่อจบตามปกติจะอัปเดตแถวเดิม ไม่เพิ่มแถวประกาศซ้ำ
- เสียงจบที่ไม่มีเสียงเริ่มจับคู่แสดง “พบเสียงจบอย่างเดียว” พร้อมเวลาของประกาศ ช่องเริ่ม/พร้อมล่าสุดเป็น “ไม่พบ” และจำนวนเป็น “—” ไม่อนุมานเงินหรือจำนวนการเติม
- เสียงพร้อมเติมที่ถูกกันไว้เพราะช่วงเสียงขาดหรือรอบเก่าหมดอายุ แสดง “ข้อมูลรอบไม่ครบ” พร้อมเหตุ ไม่เปิดรอบใหม่ข้ามขอบเขตที่ยังไม่ทราบ
- ประกาศที่ยืนยันแต่ซ้ำ ย้อนหลัง หรือซ้อนกับรายการก่อนแสดงเหตุว่าไม่นับเพิ่ม ไม่อาศัยเพียง `session_id IS NULL` เพราะบางรายการที่ไม่ได้รวมเข้ารอบยังอ้าง ID ของรอบที่กำลังเปิดได้

รายการประกาศเดี่ยวเป็น projection สำหรับหน้าจอเท่านั้น ไม่สร้าง session, API job หรือภาพหลักฐานเทียม ไม่ปิดรอบเก่าข้ามช่วงเสียงขาด และไม่แก้ ledger/checkpoint เดิม เมธอดส่งข้อมูลและ `list_sessions()` ยังอ่านเฉพาะรอบจริงตามเดิม

ข้อมูลประกาศเดิมที่ยังเก็บอยู่จะแสดงได้โดยไม่ backfill หรือเปลี่ยน schema รักษา retention สามวันและหน้าต่างล่าสุดรวมไม่เกิน 200 รายการตามเวลาเริ่มของข้อมูล มีลำดับ tie ที่คงที่ ID บนหน้าจอใช้ hash ไม่แสดง source key หรือ reason text นอกชุดที่กำหนด การล้างข้อมูลหมดอายุเดิมไม่ได้เปลี่ยน

การอ่านดึงไม่เกิน 200 รายการจากแต่ละกลุ่มก่อนรวมเลือก 200 แถว ไม่ได้หมายความว่า SQLite อ่านหรือเรียงดัชนีเพียง 400 แถว การเรียงประกาศตามเวลาแหล่งอาจต้องเรียงข้อมูลที่ยังไม่หมดอายุเพิ่มเติม

การพิสูจน์ก่อนปรับช่วงอ้างอิงเสียงเริ่ม ใช้คลิปที่ผู้ใช้ส่งยาวประมาณ 45 วินาทีผ่าน audio core และ profile FV2 เดิมช่วง Ready 2–6 วินาที พบเสียงจบหนึ่งครั้งที่ช่วงประมาณวินาที 39.03–41.03 แต่ไม่มีเสียงพร้อมเติม จากนั้นมีหนึ่งแถวประกาศเดี่ยวใน reader ไม่สร้างรอบหรือ API job การยืนยันเกิดระหว่างเสียงเงียบสังเคราะห์ 20 วินาทีต่อท้ายเพื่อรอ lookahead โดยช่วงหลักฐานเสียงจริงอยู่ภายในคลิป ไม่ถือ EOF หรือความเงียบเป็นเสียงจบ

การแก้ตรวจเสียงเริ่มภายหลังใช้ช่วงอ้างอิง 4–8 วินาที ทำให้คลิปเดิมได้ Ready และ End ครบเป็นรอบ ดู [เสียงพร้อมเติมเมื่อมีเสียงหยอดแทรก](noisy-ready-reference-th.md) ส่วนประกาศเดี่ยวจากเหตุอื่นยังแสดงในประวัติตามสัญญาข้างต้น ทั้งสองการทดสอบเป็น replay ในเครื่อง ไม่ใช่การตรวจ profile/config/RTSP จริงของ VPS หรือการยืนยันการส่งถึงโทรศัพท์
