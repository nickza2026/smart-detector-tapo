# แจ้งสุขภาพระบบภาพและเสียงเข้า Notify API

## การเปิดใช้

ใช้ Notify API Base URL และ Application API Key ที่บันทึกไว้ในส่วน Notify API เปิดแจ้งเตือนอัตโนมัติและตัวเลือกแจ้งระบบภาพ/เสียงขัดข้อง บันทึกการตั้งค่าขณะหยุดงาน จากนั้นเริ่มเฝ้าภาพ/เสียงตามปกติ การเปิดโปรแกรมหรือแก้ช่องคีย์โดยยังไม่บันทึกไม่ใช่การเริ่มส่ง health alert

ค่าเริ่มต้น: ผิดปกติต่อเนื่อง 30 วินาทีก่อนแจ้ง และแจ้งซ้ำทุก 900 วินาที (15 นาที) ขณะยังผิดปกติ ตั้งได้ 1–3600 วินาทีสำหรับระยะก่อนแจ้ง และ 60–86400 วินาทีสำหรับแจ้งซ้ำ การปิดแจ้งเตือนอัตโนมัติหลักปิด health alert ด้วย

## ภาพ

เริ่มตรวจเมื่อผู้ใช้เริ่มการวิเคราะห์ที่คาดว่าจะมีภาพให้ตรวจ ไม่อาศัยเพียง process พร้อมทำงานหรือสถานะรับภาพ healthy ต้องมีผลวิเคราะห์จากภาพใหม่ที่ผ่านหลักฐาน freshness และข้อจำกัดเดิม พร้อมผลที่เชื่อถือได้ PRESENT หรือ EMPTY

จับแนวภาพไม่ได้ ไม่มีภาพใหม่ที่ตรวจได้ ภาพหมดอายุ ผลไม่ทราบ หรือ process ที่จำเป็นหยุดผิดปกติถือว่ายังตรวจระบบไม่ได้ คะแนนความต่างสำหรับวัตถุค้างไม่ใช่คะแนนสุขภาพกล้อง และภาพที่เนื้อหาไม่เปลี่ยนแต่ยังมีหลักฐานภาพใหม่ไม่ถูกแจ้งว่าเสียเพียงเพราะภาพนิ่ง

## เสียง RTSP

เริ่มตรวจเมื่อยินยอมและเริ่มฟัง RTSP จริง คง incident เดิมระหว่างลองแหล่งเดิมใหม่ การ reconnect หรือ status heartbeat อย่างเดียวไม่ยืนยันว่ารับเสียงกลับมาแล้ว ต้องมีข้อมูล PCM ที่เดินหน้าและผ่านการประมวลผล/บันทึกตามเส้นทางเดิม

เสียงเงียบ RMS เป็นศูนย์ ไม่มีคำประกาศ หรือยังไม่มี ready/end ไม่ใช่ความเสียหาย หาก PCM ยังเดินและใช้ได้ ส่วนขาดการเชื่อมต่อ ไม่มี audio track ไม่มี PCM ใหม่ ข้อมูลเวลาเสียงไม่ผ่าน หรือระบบฟังหยุดเพราะ error/การบันทึกประวัติมีปัญหาเป็นเหตุแจ้งได้

## จังหวะและการยกเลิก

ระบบที่ไม่ส่งข้อมูลหลังผู้ใช้เริ่มเฝ้าเริ่มด้วยช่วงรอ ไม่แต่งสถานะว่า healthy ภาพและเสียงมี incident แยกกัน เหตุที่สลับชื่อระหว่างยังเสียไม่เริ่มตัวจับเวลาใหม่ ไม่มีการยิงชดเชยหลายข้อความเมื่อพลาดหลายรอบเวลา

แจ้งกลับมาปกติหนึ่งครั้งเมื่อเคยได้รับการยืนยันจาก Notify API ว่ารับคำขอ fault แล้ว และมีหลักฐานใหม่ที่เดินต่อเนื่องอย่างน้อย 30 วินาที ช่วงห่างระหว่างหลักฐานไม่เกิน 8 วินาที การกลับมาเพียงหนึ่งครั้งไม่ปิด incident แล้วเริ่มแจ้ง fault ใหม่ หากข้อมูลกลับมาแวบเดียวแล้วหายยังเป็น incident เดิมและใช้ระยะแจ้งซ้ำเดิม ไม่ถือว่าเงียบหายจาก log หรือ process เริ่มใหม่คือการกู้คืน

หน้าเสียงแสดงความสดและอายุ PCM ล่าสุดแม้ไม่มี decoder error ความสดของ snapshot เสียงกับตัวแจ้งใช้เกณฑ์เดียวกัน 8 วินาที คิว telemetry ที่เต็มทิ้งรายการเก่าหนึ่งรายการแล้วลองเก็บล่าสุดแบบไม่รอ ไม่ใช่คิว PCM หรือเหตุการณ์การเงิน การเลื่อน GUI heartbeat ไม่ทำให้ PCM สดขึ้น

กดหยุดเอง ปิดโปรแกรม ปิดการแจ้ง หรือเปลี่ยน scope ยกเลิกข้อความที่ยังไม่ได้เริ่มส่ง ไม่แจ้งว่าเป็นความเสียหายหรือกลับมาปกติ ข้อความ HTTP ที่เริ่มส่งแล้วถอนคืนไม่ได้ คำตอบของ scope เก่าจะไม่เริ่มส่งซ้ำหรือกู้คืน scope ใหม่

ตัวส่ง health อยู่ฝั่งโปรแกรมหลัก แยกจาก Worker และไม่ใช้ฐานข้อมูลประวัติเป็นคิวสุขภาพ งานส่งมีขอบเขตจำกัดและไม่บล็อก GUI ข้อความ fault/reminder ใช้ importance ที่ตั้งไว้ (`normal` เงียบ หรือ `critical` ปลุกต่อเนื่องจนกดรับทราบในมือถือ) ส่วนกลับมาปกติใช้ `normal` เสมอ ซึ่งไม่หยุด critical ที่กำลังดังอยู่ ความล้มเหลวหรือ timeout ไม่ถูกแสดงว่าสำเร็จ

แต่ละ notice ใช้ `alert_id` และ `Idempotency-Key` เดิมตลอดการลองซ้ำ (`health-<scope สุ่มต่อชุดเฝ้า>-<serial>`) ส่ง POST ครั้งเดียวต่อรอบ รอบแจ้งปกติเริ่มนับหลัง Notify API ตอบ 202 หากส่งไม่สำเร็จหรือไม่ทราบผล จะพัก 30 และ 60 วินาทีก่อนลองเพิ่ม รวมไม่เกินสามครั้งต่อชุด จากนั้นรอรอบแจ้งซ้ำที่ตั้งไว้ การลองซ้ำด้วยคีย์เดิมหลังคำตอบหายจึงไม่สร้างการแจ้งซ้ำ ส่วนผลที่ server สรุปไว้แล้ว (เช่น 502 provider_failed) จะได้ผลเดิมกลับมาโดยไม่ส่งใหม่ reminder และ recovery เป็น notice ใหม่ที่มี ID ใหม่

## ข้อจำกัด

Notify API ตอบ 202 ไม่ใช่หลักฐานว่ามือถือดังหรือผู้ใช้รับทราบ หากไม่ได้รับคำตอบก็อาจไม่ทราบแน่ชัดว่าผู้ให้บริการรับแล้วหรือไม่ หาก GUI/โปรแกรมทั้งตัว VPS หรือเครือข่ายหยุด ระบบในเครื่องเดียวกันอาจส่งไม่ได้ กรณีนั้นต้องใช้ watchdog ภายนอกซึ่งไม่ได้รวมในงานนี้

ไม่มี URL RTSP คีย์ path ฐานข้อมูล ภาพ เสียง หรือ exception ดิบในข้อความ health ไม่เปลี่ยน acoustic thresholds, การวิเคราะห์เงิน, payload/API, TTL หรือ guard ความปลอดภัยของฐานข้อมูล และไม่ทำให้การเปิดโปรแกรมเริ่มฟังหรือส่ง API เอง

งานนี้ตรวจด้วยข้อมูลจำลอง/fake sender เท่านั้น ยังไม่ได้ทดลอง Notify API จริงหรือยืนยันการทำงานบน VPS และยังไม่ได้ลงนามหรือเผยแพร่รุ่นนี้
