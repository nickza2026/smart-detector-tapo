## เป้าหมายและสิ่งที่ยังไม่อ้าง

ผู้ใช้เห็นMEmuเป็นLiveปกติแต่ข้อความยืนยันLiveไม่ผ่านขึ้นบ่อย เมื่อ2พ.ย.21:25:07บันทึกเดิมมีเพียงui_unverified จึงแยกไม่ได้ว่าเป็นการรอผลตรวจ/หมดอายุ, ADBtimeout, รอlock หรือหน้าที่อ่านไม่ผ่าน ตัวอย่างป๊อปอัปดูต่อ21:23:18ที่กู้แล้ว21:23:21ไม่พิสูจน์ว่าทุกครั้งเป็นป๊อปอัป

รุ่นนี้เพิ่มการวัด/แยกเหตุและแก้การทิ้งรหัสสาเหตุของข้อผิดพลาดที่ระบุได้ **ยังไม่อ้างว่าหยุดหมดอายุบ่อยแล้วหรือเฝ้าเครื่องจริงได้ต่อเนื่อง** ไม่เพิ่มTTL/เปลี่ยนจุดเริ่มอายุ/ปิดguard/ลดเกณฑ์Live/เปลี่ยนmatcherหรือเวลาตรวจธุรกรรมจากการเดา

## ใช้ตัวใหม่

1. หยุดงานและปิดSmartTapoเก่า เปิด`.tools/diagnostic-v29/SmartTapo.exe` เก็บconfig/data/profile/คีย์เดิม ไม่ต้องreset/แก้JSON
2. เปิดLiveกล้องเดิมและเริ่มCapture/Workerตามปกติด้วยตัวเอง การพัฒนาไม่ได้กดMEmu/เริ่มรับเสียงหรือภาพ/รีสตาร์ตตัวที่ผู้ใช้เปิดไว้
3. ดูlogใน**3. เริ่ม / หยุด** มีบรรทัดเฉพาะผลตรวจUIพร้อมreasonและเวลาข้างข้อความเดิม ไม่ต้องเปิดรับเสียงเพื่อให้เกิดdiagnosticsนี้

## อ่านสถานะ

- **ยืนยันหน้า Live สำเร็จ**: การอ่านUIรอบนี้ผ่านและหลักฐานยังไม่หมดอายุ ไม่ใช่ยืนยันว่าทั้งกล้อง/เสียง/การแจ้งเตือนปกติทุกระบบ
- **หลักฐานหน้า Live หมดอายุขณะรอผลตรวจใหม่** `[proof_expired]`: ผลใหม่ยังไม่พร้อมหรือเมื่อรับผลแล้วหลักฐานเก่าเกินอายุ จึงพักส่งเฟรม ไม่มีเหตุให้สรุปว่าหน้าMEmuที่คนเห็นผิด คำเตือนนี้จำกัดไม่ถี่กว่าทุก5วินาที ไม่พิมพ์ทุกเฟรม
- **ตัวตรวจหน้า Live ล้มเหลว**: เช่น`adb_timeout`หมดเวลารอ, `adb_unavailable`เรียกADBไม่ได้, `adb_nonzero`คำสั่งล้มเหลว, `ui_lock_busy`รอlockไม่สำเร็จ, `ui_lock_unavailable`เปิดlockไม่ได้
- **อ่านหน้าแล้วไม่ยืนยัน Live**: เช่น`camera_not_confirmed`ชื่อกล้องไม่ยืนยัน, `incomplete_live_layout`องค์ประกอบไม่ครบ, `observed_playback_layout`พบPlayback, `live_inactivity_confirmation`พบป๊อปอัปดูต่อ, `foreground_changed_or_unknown`แอปด้านหน้าเปลี่ยนหรือไม่ยืนยัน
- `ui_dump_failed`สร้างUIdumpไม่ได้, `ui_hierarchy_invalid`โครงสร้างUIไม่ถูกต้อง, `verification_exception`ข้อผิดพลาดที่ยังไม่มีรหัสเฉพาะ ไม่มีการแสดงerrorดิบที่อาจมีข้อมูลส่วนตัว

## อ่านเวลาโดยไม่ตีความเกินหลักฐาน

- **นับจากขอตรวจ**: เวลาตั้งแต่ยื่นงานจนถึงจุดที่โปรแกรมรายงาน รวมการรอ/การรับผลกลับด้วย ไม่ใช่เวลาADBเพียงอย่างเดียว
- **อายุหลักฐาน**: อายุที่ทราบ ณ จุดรายงาน ถ้าไม่มีหลักฐานที่ใช้ได้หรือยังไม่ทราบจะแสดง**ยังไม่ทราบ** ไม่ใส่0ปลอม
- **lock**: เวลารอเข้าUIlock รวมการเข้าซ้ำที่วัดได้ ไม่ใช่เวลาถือlockทั้งรอบ
- **foreground**: เวลาตรวจแอปด้านหน้าก่อนและหลังอ่านรวมกัน
- **dump/read/cleanup/parse**: เวลาสร้างdump/อ่านไฟล์/ล้างไฟล์ที่โปรแกรมสร้างเอง/ตรวจโครงสร้างและจำแนกหน้า แต่ละขั้นมีเวลาจากตัวจับเวลาจริง
- **ขั้น**: ขั้นที่ล้มเหลวหรือขั้นสุดท้ายที่เสร็จเมื่อรับผลแล้ว ขณะpendingยังไม่อ่านค่าที่threadอื่นกำลังแก้ จึงอาจเป็น**ยังไม่ทราบขั้นตอน** ไม่เดาว่าค้างdumpหรือlock
- ขั้นที่ยังไม่เกิด/ไม่ได้วัดเป็น**ยังไม่ทราบ** ผลรวมแต่ละเวลาอาจไม่เท่าค่านับจากขอตรวจเพราะมีช่วงรอ/รับผล/งานอื่น ไม่อ้างCPUหรือเน็ตจากเวลานี้อย่างเดียว

การตรวจหนึ่งรอบยังมีได้เพียงหนึ่งงานพร้อมกัน ผลปฏิเสธ/ผิดพลาดไม่ต่ออายุหลักฐาน และอายุยังนับจากเริ่มขอตรวจ ไม่ใช่เวลาที่รับผล หน้าคนดูปกติไม่ได้ยืนยันว่าADBอ่านUIสำเร็จทันเวลา ในทางกลับกันwarningไม่พิสูจน์ว่ากล้องเสีย

## หลักฐานและความเป็นส่วนตัว
