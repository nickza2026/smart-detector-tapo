# SmartTapo .23 candidate — Windows-login startup และสุขภาพตัวฟัง

ผลจำลอง/source/frozenEXEไม่ใช่bootจริงหรือรับประกันจับเสียงลูกค้าครบ ตรวจreceiptของชุดส่งมอบ ไม่ใช้ผลbuildเก่าแทนรุ่นใหม่

## ตั้งครั้งแรก

1. หยุดงานและปิดตัวเก่าก่อน เปิด`.tools/diagnostic-v23/SmartTapo.exe`โดยตรง ไม่ใช่shortcutเก่า เก็บconfig/data/profile/baselineเดิม อย่าย้าย/ลบEXEหลังลงstartup หากเปลี่ยนที่อยู่ให้เปิดEXEใหม่แล้วบันทึกstartupใหม่
2. ตั้งค่าเดิมต้องบันทึกแล้ว: adb.exe/Serial/ชื่อกล้อง/MEmu.exeและภาพช่องว่างที่ยืนยันแล้ว สำหรับเครื่องที่ตรวจreadonlyระหว่างทำงานมีpathMEmuที่บันทึกและไฟล์อยู่แล้ว ไม่ต้องกรอกใหม่ถ้ายังถูกต้อง
3. แท็บเสียงเลือกอุปกรณ์เสียงขาออกเฉพาะMEmuที่ใช้เดิมและprofileที่เตรียมให้ ไม่เลือกdefaultหรือไมค์อื่น หากยังไม่มีGUIDให้รีเฟรชรายการ เสียงผ่านCABLEอาจไม่ได้monitorออกลำโพงและไม่ควรเปลี่ยนWindowsdefaultเพื่อบังคับให้ฟังได้
4. ไปแท็บ**Windows startup** ติ๊กยินยอมเปิดCapture/Workerและติ๊กยินยอมฟังต่อเนื่องด้วย จากนั้นกด**บันทึก / ผูกการยินยอม Windows startup** ยืนยันdialogหนึ่งครั้ง ช่วงผูกนี้ต้องMEmu/ADBเดิมพร้อมเพื่ออ่านidentityAndroid แต่ยังไม่เริ่มฟังทันที
5. ครั้งต่อไปเมื่อเข้าWindowsบัญชีนี้จะเปิดEXEและflowอัตโนมัติ ปุ่ม**ลองเริ่มจากค่าที่ผูกไว้**คือการสั่งflowจริงด้วยตัวเอง ไม่ใช่โหมดจำลอง จึงใช้เฉพาะเมื่อตั้งใจเริ่มMEmu/Tapo/ภาพ/เสียงแล้ว หยุดหลักยกเลิกการลองใหม่ในsessionนั้นได้

ติดตั้งเฉพาะentryที่เป็นเจ้าของชื่อ`SmartTapo-login.vbs`ในStartupfolderของบัญชีWindowsปัจจุบัน ไม่ใช้สิทธิ์admin/service/registryRun ไม่ลบentryของแอปอื่น ปิดได้โดยหยุดงาน เอาเครื่องหมายstartupออกและกดบันทึก หากมีentryชื่อเดียวกันที่ไม่ใช่ของแอปจะไม่เขียนทับ Windows Script Hostที่ถูกปิดโดยpolicyอาจทำให้entryไม่ทำงาน ต้องตรวจนโยบายเครื่อง ไม่ข้ามpolicyเอง

## อ่านสถานะ

- รอMEmu/ADB/Live: retryแบบมีพัก ไม่เลือกSerialหรือกล้องอื่น ไม่อ้างว่าเปิดprocessแล้วเท่ากับLiveพร้อม
- สั่งเริ่มCapture/Worker: ดูสถานะจริงในแท็บเริ่ม/หยุด หากcontrollerปฏิเสธเริ่มไม่รายงานว่าสำเร็จและไม่เปิดเสียงต่อโดยเงียบ
- รอendpoint/profileเดิม: ต้องGUID/ชื่อ/รูปแบบตรงกัน หมายเลขindexเปลี่ยนได้แต่GUIDเปลี่ยนหรือซ้ำไม่ใช้แทน ต้องหยุดแล้วผูกใหม่เมื่อผู้ใช้เปลี่ยนรายการจริง
- ส่งให้ตัวเฝ้าเสียง: ดูแท็บเสียงว่ากำลังตรวจLive/รับข้อมูล/รอข้อมูล/retryอะไร ไม่เท่ากับจับประกาศครบ
- ประวัติสุขภาพเก็บที่`data_dir/logs/listener-health.jsonl`หมุนเวียน2MB+สำรอง2ไฟล์ เก็บattempt/reap/PIDที่มีจริง/retry/errorcode/countersแบบจำกัดความถี่ ไม่เก็บPCM/ข้อความพูดหรือkey ตัวเลขที่ไม่มีไม่ใส่0 ใช้diagnoseเหตุการณ์ใหม่ ไม่ย้อนสร้างเสียงเก่า
- ถ้าlogสุขภาพเขียนไม่ได้แสดงแยกจากสถานะฟัง ไม่ปิดตัวฟังหรือเอาข้อความlogไปกลบสาเหตุเสียงจริง

## ขอบเขตที่ผู้ใช้ยืนยัน 31 ตุลาคม 2026 11:30

เมื่อเข้าWindowsบัญชีผู้ใช้ ให้เปิดSmartTapo/MEmu/Tapo เข้ากล้องที่บันทึกไว้ ยืนยันหน้าLive แล้วเริ่มCapture/Workerและตัวฟังเสียงต่อเนื่องจากอุปกรณ์/profileที่ยืนยันไว้ ตั้งค่าครั้งเดียวไม่ต้องกลับมากดเริ่มฟังทุกครั้ง ไม่ใช่serviceก่อนlogin และไม่ได้อนุญาตrebootเครื่อง/ติดตั้งstartupจริง/เปิดเสียงหรือจับเสียงจริงระหว่างพัฒนา

Startupต้องเป็นopt-inแยกชัดเจน ค่าconfigเดิมไม่เปิดเอง ผูกสิทธิ์กับกล้อง/อุปกรณ์เสียง/profileที่บันทึก ไม่เลือกไมค์หรืออุปกรณ์defaultสำรอง ไม่ข้ามlogin Tapo/Playback/กล้องผิด/สิทธิ์เสียง ไม่เปลี่ยนdefaultเสียง/routing/volumeWindows

ถ้าเปิดMEmuอยู่แล้วไม่เปิดซ้อน ถ้าบูตช้า/ADBหรือLiveยังไม่พร้อมให้รอและลองใหม่แบบมีพัก มีสถานะที่อ่านรู้เรื่อง กดหยุดต้องหยุดทั้งflow/retryและงานที่เปิด ไม่กู้กลับเองหลังผู้ใช้กดหยุด ไม่ปิดMEmuที่ผู้ใช้เปิดเองเมื่อปิดSmartTapo

อุปกรณ์เสียงอาจเปลี่ยนหมายเลขหลังreboot ต้องยืนยันidentityเดิม ไม่อ้างว่าindexเดิมเท่ากับอุปกรณ์เดิม เมื่อprofile/กล้อง/อุปกรณ์เปลี่ยนหรือระบุไม่ได้ต้องหยุดรอการยืนยัน ไม่ฟังเสียงอื่นแทนโดยเงียบ
