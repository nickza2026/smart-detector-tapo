# SmartTapo .16 candidate — ลดเวลารอ retry ของเสียงสะดุด

รุ่น `2026-10-30.16` เปลี่ยนเฉพาะเวลารอก่อนเริ่มความพยายามกู้ใหม่ ไม่ใช่การรับรองว่ากลับมาฟังเสียงได้ภายใน 2 วินาที รวมความสามารถ/ข้อจำกัดของ .15 ตาม `refueling-v15-th.md` และยังเป็น candidate สำหรับทดสอบ ไม่ได้ deploy หรือส่งเข้า VPS

## สิ่งที่เร็วขึ้น

- อาการชั่วคราว `audio_clock_discontinuity`, `audio_timeout`, `live_navigation_changed`, `live_check_unavailable` ลองใหม่ทันทีหลัง reaping ตัวเก่า จากนั้นเว้น `0.25 / 0.5 / 1 / 2` วินาที สูงสุด 2 วินาที แทนการไต่รอถึง 30 วินาที
- ไม่เริ่มตัวฟังใหม่ซ้อนตัวเดิม แม้ SDK เก่ายังไม่คืน ไม่เพิ่ม process แบบไม่จำกัด และปุ่มหยุดยังยกเลิกการลองใหม่
- โปรไฟล์ผิด/อุปกรณ์เปลี่ยน/หลักฐานกล้องไม่ผ่าน/ข้อผิดพลาดอื่นยังใช้ backoff เดิม `1 / 2 / 5 / 10 / 30` เพื่อไม่เปิดอุปกรณ์ผิดหรือวนหนักโดยไม่มีข้อมูล
- ทุกความพยายามยังตรวจโปรไฟล์เดิม อุปกรณ์เดิม และ Live สดใหม่ก่อนเปิดรับเสียง ไม่ใช้ cached Live ข้าม session ไม่ผ่อน TTL หรือเกณฑ์ audio 2 วินาที และไม่ต่อ PCM คนละ epoch

เวลาเปิด stream จริงยังรวมการปิดตัวเก่า, ADB/UI, ตรวจโปรไฟล์, spawn และ SDK ด้วย จึงยังไม่มีคำรับรอง SLA 2 วินาที ต้องวัดบนเครื่องจริงโดยแยกเส้นทางเสียงจากงานหลักก่อน

## หากมีลูกค้าระหว่างเสียงขาด

เสียงที่ไม่ได้รับไม่สามารถสร้างกลับจาก retry ได้ ถ้าเคยเห็นประกาศเริ่มแล้วเสียงขาด ประวัติที่ถูกขัดจังหวะต้องคงความไม่ครบ ไม่สร้างการจบปลอมและไม่โยงลูกค้าคนใหม่เป็นคนเดิม หากพลาดทั้งประกาศเริ่มและจบ ลูกค้ารายนั้นอาจไม่ปรากฏในประวัติเลย ไม่ใช่หลักฐานว่ามีลูกค้า 0 ราย

ระบบนี้เฝ้าภาพ/เสียง ไม่ใช่แหล่งยืนยันธุรกรรมหรือเงิน หากต้องการรับประกันไม่ตกหล่นทุกราย ต้องตกลงแหล่งข้อมูลต้นทางที่เชื่อถือได้จากตู้เพิ่มเติม ไม่เอาข้อมูลที่เดาจากช่วงเสียงขาดมาชดเชย ไม่มีการเชื่อมตู้/สั่งหยุดตู้/ใช้เงินจริงในรอบนี้

ZIP อยู่บนเครื่องหลัก ไม่ใช่ไฟล์ที่ส่งเข้า VPS แล้ว ใช้เป็น candidate ทดสอบก่อน เมื่อจะอัปเดตให้หยุดทุกงาน ปิด EXE เก่า แทนเฉพาะ EXE ในโฟลเดอร์เดิม/บัญชี Windows เดิม รักษา config, data, ประวัติ, baseline และโปรไฟล์ ไม่เปิดสองรุ่นพร้อมกัน เสียงตัวอย่าง prepared-profile เหมือนรุ่นก่อน

กรอบฟ้านาฬิกาปรับได้อยู่แล้ว: เปิดภาพ ADB ลากครอบตัวเลขเวลาในวิดีโอ ติ๊กยืนยันแล้วบันทึกเฉพาะกรอบนาฬิกา ไม่เปลี่ยนกรอบแดงหรือภาพช่องว่าง รุ่นนี้ไม่ได้เพิ่มตัวแก้กรอบซ้ำ

## ขอบเขตการตรวจ

มี regression แบบ virtual clock ให้ล้มก่อนแก้เพราะรอ 1 วินาทีแทน retry ทันที แล้วผ่านหลังแก้ ทดสอบ 60 transient failures, backoff แบบเก่าสำหรับ profile ผิด, ไม่มี process ซ้อน, Stop ชนะ, profile/device freeze, navigation fence และข้อมูลขาดไม่ถูกต่อเป็นรอบปกติ

ผล fullsuite/source snapshot/frozen GUI และ SHA256 ใช้ receipt ของชุดที่สร้างจริง ไม่ใช้จำนวน focused tests หรือ compile แทนผลทั้งหมด การ smoke ใช้ synthetic PCM/SQLite และหน้าต่างนอกจอเท่านั้น ไม่เปิด hardware/ADB/เสียงจริง

**ยังไม่ยืนยัน:** เวลารวมกู้เสียงจริงของ .16, autoContinue จริงข้าม 5 นาที, การเฝ้าหลังปิด Viewer บน VPS, ความแม่นยำประกาศ/Worker จริงและโทรศัพท์ ยังไม่ส่ง Pushover ไม่เปลี่ยน route/default/volume/mute ไม่เปิดไมค์และไม่เล่นเสียงทดสอบ

ก่อนทดสอบเสียงจริงต้องตรวจ Windows Default/Communications และแหล่งเสียง CABLE ปัจจุบันอีกครั้ง ผู้ใช้แจ้งว่าเสียงกลับมาแล้ว แต่ไม่ถือว่าค่า role และการแยก source ยืนยันแล้วอัตโนมัติ ไม่มีการฟังจริงในงานแก้ retry นี้
