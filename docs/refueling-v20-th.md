# SmartTapo .20 candidate — ตั้งช่วงรับภาพและกู้คำถามดูต่อซ้ำ

## ตั้ง 0.5 วินาทีใน UI

แท็บตั้งค่ามีช่อง **ช่วงรับภาพ (วินาที)** และปุ่ม **ใช้ 0.5 วินาที** กดปุ่มแล้วบันทึกการตั้งค่าโดยหยุด Capture/Worker/ตัวฟังเสียงก่อน ค่าที่บันทึกเดิมยังไม่ถูกแก้ระหว่างโปรแกรมทำงาน ปุ่มเป็นการเติมช่อง ไม่ใช่เริ่มจับภาพหรือเปลี่ยนเสียงWindowsให้เอง

0.5วินาทีเป็นช่วงที่ร้องขอ ไม่รับประกัน2ภาพใหม่ต่อวินาทีจริง หากADB/การส่งPNG/การตรวจหน้าใช้เวลานานกว่านั้น จะไม่ได้เร่งสร้างเฟรมปลอมหรือค้างคิวไล่งานย้อนหลัง งานCPU/ดิสก์อาจเพิ่มขึ้น ไม่ได้เปลี่ยนมาเป็นRTSPและไม่รับทุกเฟรมวิดีโอกล้อง

เวลาเปลี่ยนช่วงรับภาพผ่านUI โปรแกรมจะคงระยะพิสูจน์เดิมไว้ด้วย นอกจากจำนวนภาพขั้นต่ำ เช่นเดิม10ภาพห่าง1วินาทีมีช่วงจากภาพแรกถึงภาพสุดท้าย9วินาที เปลี่ยนเป็น0.5วินาทีไม่ทำให้เตือนหลังเพียง4.5วินาที เงื่อนไขclearก็ไม่ถูกเร่งตามจำนวนภาพอย่างเดียว ภาพขาด/หน้าเปลี่ยน/หลักฐานใช้ไม่ได้ไม่ยืดหลักฐานเก่าเป็นช่วงต่อเนื่อง

นาฬิกาบนภาพอาจเดินวินาทีละครั้ง ภาพย่อยที่clockซ้ำจะไม่เพิ่มคะแนนค้าง/clearหรือส่งแจ้งเตือน เพียงรอเฟรมที่ยืนยันclockเปลี่ยนภายในช่วงปลอดภัย ไม่รีเซ็ตหลักฐานทันทีเพราะจับถี่กว่านาฬิกา ถ้าclockหยุดจริงเกินช่วงที่ยอมรับหรือหน้า/sessionเปลี่ยนจะรีเซ็ต ไม่ยกภาพซ้ำให้เป็นภาพสด เพิ่มจำนวนภาพที่รับไม่ใช่การรับประกันว่าจะรู้ว่าแบงค์ผ่านทุกใบหรือว่าเครื่องรับเงินแล้ว

## พยายามกู้คำถาม5นาทีต่อเนื่อง

สาเหตุที่ตรวจจากlogเครื่องหลักเวลา00:24–00:25วันที่31ตุลาคมคือ`selected_camera_authorization_missing` ระบบวนกลับมาแต่ปฏิเสธก่อนกดเพราะหลักฐานLiveเดิมหมดอายุ ไม่ใช่หลักฐานว่าปุ่มกดเสีย ขณะนั้นruntimeและhashตรง.18 แม้เคยส่ง.19ให้แล้ว แต่.19ยังใช้ข้อจำกัดกู้นี้เช่นกัน การเปลี่ยนรุ่นอย่างเดียวโดยไม่แก้กลไกจึงไม่ใช่คำตอบ

ตามการอนุญาตใหม่ .20ให้ทำเฉพาะ **ปุ่มต่อไปของdialogTapo5นาทีที่รู้จัก** จากหลักฐานหน้าปัจจุบันบนอุปกรณ์ที่เลือก แม้dialogบังชื่อกล้อง/หลักฐานLiveครั้งก่อนหมดอายุ ยังไม่ถือdialogเป็นLive ไม่ใช้พิกัดเก่า ไม่กดCancel/Close/Talk/Alarm/ตั้งค่ากล้อง ไม่กดในPlayback/หน้าแอปอื่น/หน้ารหัสผ่าน/กล้องชื่อผิดที่มองเห็น

หลังdismissต้องอ่านใหม่ ตรวจกล้องเดิมและยืนยันLiveใหม่ หากมีรีเฟรชต่อ ต้องตรวจชื่อกล้อง/ปุ่มรีเฟรชจากหลักฐานสดก่อน ไม่ปล่อยภาพค้างเป็นภาพLiveหรือนับว่ากู้สำเร็จจากการtap

แต่ละชุดกู้มีขอบเขตจำนวนครั้งและใช้lockร่วม เมื่อยังไม่ผ่านลูปเฝ้าจะลองใหม่แบบมีช่วงพักตราบที่งานยังทำงาน ไม่มีกำหนดหยุดเพียงเพราะเคยล้มเหลวสองสามครั้ง แต่ก็ไม่กดรัว/สร้างงานซ้อน **หยุดทั้งหมด/ปิดแอปต้องยกเลิกการพยายามต่อ** หน้าไม่รู้จักยังปฏิเสธ ไม่ใช่บอกว่าจะกดทุกป๊อปอัปหรือรับประกันทุกกรณี

## สิ่งที่ยังเหมือนเดิม

- มีแท็บRefuelingAPIv1จาก.19 ใช้BaseURLเช่น`https://dashboard.example/api` ไม่ใช่endpointทั้งเส้น keyกรอกในแอป/DPAPIผูกURL+กล้อง ไม่ส่งในแชต
- เปิดสิทธิ์→บันทึก→ยืนยันคิว→เริ่มส่ง จึงส่งภาพและเหตุการณ์ ไม่ยิงปลายทางจริงจากการเปิดโปรแกรมหรืออัปเดตEXEเฉย ๆ รายละเอียด`refueling-v19-th.md`
- การจับประกาศเสียง/การสร้างรอบเติมและการตรวจวัตถุค้างเป็นคนละระบบ การมีแต่เสียงจบไม่สร้างเวลาเริ่มย้อนหลัง งานรอบนี้ไม่ได้เพิ่มUIประวัติประกาศที่ผูกเป็นรอบไม่ได้ ซึ่งพักไว้ตามคำขอ ไม่แก้ข้อมูลเก่าเพื่อให้ดูมีรายการ
- ไม่เปลี่ยนrouting/volume/ไมค์ ไม่เปิดเสียงทดลอง ไม่ติดตั้งservice ไม่เปลี่ยนค่าในมือถือ/กล้องหรือdeployเซิร์ฟเวอร์
