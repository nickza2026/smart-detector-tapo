# Ready จากเสียงอ้างอิงสองช่วง

V54 คง Ready หลักช่วง 4–8 วินาทีของ WAV เดิม และเพิ่มช่วงสำรอง 2–6 วินาทีจากไฟล์เดียวกัน เกณฑ์ raw 0.6, temporal 0.2 และอย่างน้อยสอง anchor ที่ 0.55 ไม่ลดลง ส่วน End คงช่วง 2–4 วินาทีและเกณฑ์เดิม 0.55/0.3 ไม่มีโมเดลหรือเสียงอ้างอิงใหม่

ช่วงสำรองระบุชัดใน `alternates` ของ Ready เท่านั้น รองรับหนึ่งช่วง ใช้เกณฑ์และ feature version ร่วมกับช่วงหลัก และรวมอยู่ใน fingerprint ของโปรไฟล์ โปรไฟล์เดิมที่ไม่มี field นี้ยังใช้พฤติกรรมและ fingerprint เดิม

การเทียบตำแหน่งอ้างอิงใช้เฉพาะระบุตัวประกาศเดียวกัน ไม่ย้ายเวลาเสียงย้อนหลัง ช่วงที่ตรงทั้งสองแบบจึงไม่กลายเป็น Ready สองครั้ง เวลาประกาศมาจากช่วงเสียงที่ตรวจพบจริง และเสียง End ที่ซ้อนกับหลักฐานยังคงเป็นความกำกวม ไม่ถูกบังคับจับคู่

WAV Ready ยาวแปดวินาที ช่วงหลักได้ 397 feature frames หลังขอบ FFT ช่วงสำรองใช้ความยาวเดียวกัน ช่วงหลักฐานสูงสุดสำหรับ lookahead เท่ากับ 5.97 วินาที และ horizon เท่ากับ 12.34 วินาที แทนประมาณ 8.34 วินาทีของโปรไฟล์ช่วงเดียว เป็นเวลารอวิเคราะห์ ไม่ใช่การเพิ่มเวลาจบหรือสร้างเสียง End ขึ้นเอง บัฟเฟอร์ยังจำกัดยี่สิบวินาที

โปรไฟล์ใหม่ต้องเลือกผ่านทางยินยอมโปรไฟล์ที่เตรียมให้ขณะหยุดงาน การตรวจอัปเกรดจำกัดเฉพาะโปรไฟล์ managed ที่ตรงกับชุดเดิมและ receipt ของกล้องนั้น ไม่ค้นหาโปรไฟล์ส่วนตัวหรือเขียนทับ custom config/threshold ไม่มีการแก้ Windows startup binding อัตโนมัติ

คลิปใหม่วันที่ 18 พฤศจิกายน 2569 เคยได้ Ready raw 0.598 ซึ่งไม่ผ่านเกณฑ์ 0.6 ของช่วง 4–8 เมื่อมีช่วงสำรอง พบ Ready ที่วินาที 9.16 และ End ที่ 22.16 รวมเป็นคู่ห่างสิบสามวินาที คลิปจริงหกไฟล์ผ่าน Ready/End อย่างละหนึ่งครั้ง เสียงลบจริงสาม WAV ไม่เกิดเหตุการณ์เพิ่ม และ Ready ต้นฉบับหนึ่ง WAV ยังได้ครั้งเดียว นี่เป็นการ replay ไฟล์ ไม่ใช่การยืนยัน RTSP, VPS, API หรือมือถือจริง

การ replay เติม PCM ศูนย์ยี่สิบวินาทีหลัง EOF เพื่อรอ lookahead เท่านั้น End ที่ยืนยันต้องมาจากเสียงจริงในไฟล์ ไม่ใช่ความเงียบหรือ EOF โปรไฟล์ที่ VPS ใช้อยู่ยังไม่ได้อ่านหรือยืนยันจากงานนี้

การรวม Ready/End หลัง gap ดู `post-gap-partial-history-th.md` ซึ่งรักษาข้อจำกัดหลักฐานไม่ครบและไม่สร้างยอดหรือ API job ใหม่จากคู่บางส่วน
