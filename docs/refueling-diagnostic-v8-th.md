# Diagnostic .8 — เก็บข้อมูลแยก Live/Playback ก่อนต่อประวัติจริง

รุ่น `2026-10-29.8` เพิ่มตัวอ่านประวัติเติมในเครื่องและเครื่องมือเก็บโครงสร้างหน้าของTapo **ยังไม่เปิดฟังต่อเนื่อง/สร้างรอบจากเสียงจริง และยังไม่มีหน้าตั้งค่าหรือการส่งwebhookอัตโนมัติ**

SQLite/checkpoint/คิว/ส่งภาพ→JSONมีโค้ดและทดสอบHTTPจำลองแล้ว ไม่ใช่dashboardที่deployจริงและไม่ใช่ผลทดสอบเสียงจากVPS

## ขั้นต่อไปบนเครื่องที่เปิด MEmu

1. ปิดSmartTapoรุ่นเก่า แล้วเปิด `.8` แทนโดยใช้configเดิม ไม่ต้องลบ/ตั้งcalibrationใหม่
2. หยุดCapture/Workerและการรับเสียง ถ้ามีแก้ADB Serialให้บันทึกการตั้งค่าก่อน
3. ในTapoเปิดหน้ากล้อง **Liveจริง** ตามปกติ ไปแท็บ **3. เริ่ม / หยุด** แล้วกด **เก็บหน้า Live** รอข้อความบันทึกเสร็จ อย่าเปลี่ยนหน้าระหว่างเก็บ
4. ในTapoเปิด **Playback** ของกล้องเดียวกัน ให้เห็นหน้าเล่นย้อนหลังจริง กด **เก็บหน้า Playback** แล้วรอเสร็จ
5. กด **เปิดโฟลเดอร์รายงานหน้า** ส่งไฟล์ `tapo-live-....json` และ `tapo-playback-....json` กลับมาเพื่อสร้างregressionแยกโหมด
6. กลับTapoไปหน้าLiveก่อนใช้Capture/Workerเดิม ไม่เปิดWorkerระหว่างกำลังดูPlayback

อ่านADBเฉพาะอุปกรณ์ที่ตั้งไว้ ไม่launch/นำทาง/เปิดกล้อง/รับเสียงให้ ไม่ดึงscreenshot ไม่เก็บrawXML/free-textที่เป็นบัญชีหรือcamera nameในรายงาน เก็บresource-id, control markersที่อนุญาต, selected/clickable, activityและbooleanว่าพบชื่อกล้องหรือไม่ ถ้าหน้าpasswordจะปฏิเสธ

ไฟล์อยู่ `data_dir/diagnostics` ไม่อัปโหลดเอง labelที่กดเลือกเป็นข้อมูลผู้ทดสอบ ไม่ใช่proofว่าหน้านั้นLive (`verified_mode`ยังเป็น`unknown`) การเก็บอาจใช้หลายวินาทีตามADB; หน้าเปลี่ยนactivityระหว่างเก็บจะไม่เผยแพร่ไฟล์

## ประวัติ/รูปและสิ่งที่ยังไม่เชื่อม

- แท็บ **ประวัติการเติม** แยกจากประวัติการหยอดแบงค์แบบภาพเดิม ไม่มีแปลงรายการเดิมหรือเติมdemoลงฐานผู้ใช้
- อ่านล่าสุด200รายการ แสดงready_count/เวลาจบว่าง/ประกาศซ้ำ/ไม่พบจบ5นาทีและเปิดภาพที่เชื่อมไว้ได้ ยังไม่มีlive producerจึงไม่ควรมีรอบใหม่ขึ้นเองจากเสียงในรุ่นนี้
- ข้อมูลเติม/รูปใหม่เก็บ72hจากสร้างรอบครั้งแรก ไม่ต่ออายุเมื่อrepeat/retry โปรแกรมตรวจcleanupแม้แท็บซ่อน ถ้าปิดโปรแกรมอยู่จะตรวจเมื่อเปิด ไม่ได้ติดตั้งbackground Windows service
- หากรอบยังไม่จบแต่ครบอายุ ลบเนื้อหาแล้วแสดงสถานะรอเสียงขอบคุณก่อนนับรอบใหม่ ไม่ให้ประกาศซ้ำหลังลบกลายเป็นลูกค้าใหม่ และcleanupไม่เลื่อนprocessed-audio timelineตามwall clockจนข้ามเสียงที่ยังรอจำแนก
- ลบเฉพาะข้อมูลใหม่ที่เป็นเจ้าของ ไม่ลบsound/calibration/config/รูปต้นฉบับ/ประวัติแจ้งแบงค์ค้างเดิม รูปที่OSไม่ให้ลบต้องรายงานerror ไม่อ้างว่าลบphysical fileหมดแล้ว
- ตัวส่งเป็นlibraryที่ทดสอบแล้วตาม [APIv1](refueling-webhook-api-th.md) ไม่ใช่เปิดเครือข่ายส่งจริงในUIรุ่นนี้ ฝั่งรับdashboardยังต้องสร้างตามcontract
- การยืนยันLive UIไม่ใช่การแยกเสียงรายprocess: WASAPI loopbackยังอาจรับแอปอื่นที่ใช้ช่องเสียงเดียวกัน ต้องไม่อ้างว่าทุกเสียงมาจากกล้อง
