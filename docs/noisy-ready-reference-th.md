# เสียงพร้อมเติมเมื่อมีเสียงหยอดแทรก

สถานะ: แก้ในซอร์สและทดสอบ replay ในเครื่อง ยังไม่ใช่ EXE รุ่นใหม่หรือการยืนยันกล้อง/โทรศัพท์จริง

## อาการและแนวแก้

คลิปที่ผู้ใช้ส่งวันที่ 17 พฤศจิกายนยาวประมาณ 45 วินาทีมีเสียงพร้อมเติมปนเสียงหยอดและเสียงจบ โปรไฟล์ FV2 เดิมตรวจพบเฉพาะ End ทั้งที่ Ready ที่ช่วงประมาณ 12.73 วินาทียังมีรูปแบบลำดับเสียงสอดคล้อง: raw NCC ประมาณ .571 ต่ำกว่า .6, anchor ประมาณ .500/.456/.758 และ temporal ประมาณ .273 ผ่าน .2 จึงไม่ผ่านทั้งคะแนนรวมและสองในสาม anchor ไม่ใช่หลักฐานว่าไม่มีเสียงเริ่ม

โปรไฟล์ที่เตรียมให้เปลี่ยนเฉพาะช่วง Ready ใน WAV อ้างอิงเดิมจาก 2–6 เป็น 4–8 วินาที ช่วงเสียงพูดส่วนหลังทนกรณีเสียงหยอดแทรกนี้ได้ดีกว่า ไม่ตัดเสียงจากคลิปใหม่ไปทำ template ไม่เปลี่ยน WAV, feature version/วิธีคำนวณ, raw .6, temporal .2, anchor สองในสามที่ .55 หรือเงื่อนไข End

ช่วงอ้างอิงยังยาวสี่วินาทีเท่าเดิม ขอบเขต RAM และ lookahead จึงไม่เพิ่ม เวลา Ready ที่รายงานเป็นต้นช่วงเสียงอ้างอิงที่ตรวจพบ ไม่ใช่เวลาหยอดเงินแรกหรือเริ่มไหลของน้ำมัน เมื่อเลื่อนไปใช้ช่วงหลัง timestamp ที่จับคู่ได้ในคลิปเดิมเลื่อนประมาณสองวินาที ไม่ย้อนเวลาเพื่อเดาเสียงที่ถูกบัง

## เปิดใช้กับโปรไฟล์เดิม

สำหรับโปรไฟล์ส่วนตัวที่โปรแกรมเคยสร้างจากชุด FV2 เดิมตรงตาม fingerprint ที่รู้จัก เมื่อหยุดแล้วกด Run All จะเสนอคัดลอกเป็นโปรไฟล์ปัจจุบันหลังยินยอมครั้งเดียวในรอบนั้น ตรวจ path/digest/สถานะซ้ำก่อนเริ่ม ไฟล์เดิมคงอยู่ การเปลี่ยน threshold, template หรือ selection ที่ไม่ผ่านหลักฐานว่าเป็นชุดเดิมไม่ถูกจัดเป็นการอัปเกรดนี้

โฟลเดอร์ `prepared-profile` เก่าข้าง EXE ที่ตรงชุด FV2 เดิมแบบตรวจครบทั้ง manifest และ WAV ไม่บังชุดใหม่ที่อยู่ในโปรแกรม ส่วนชุดปรับเองยังมีลำดับความสำคัญเดิม ชุดเสียหรือไม่ปลอดภัยยังถูกส่งต่อให้ validator ปฏิเสธ ไม่ข้ามไปใช้ fallback เงียบ ๆ

การเปลี่ยน EXE เพียงอย่างเดียวไม่เขียนทับ private profile หรือ Windows startup binding หากใช้ปุ่มเริ่ม RTSP ตรง ๆ ให้เลือก “ใช้โปรไฟล์จากเสียงที่เตรียมให้” ขณะหยุดก่อนเริ่ม หากต้องการใช้โปรไฟล์ใหม่นี้กับ saved startup binding ให้ผูกใหม่ผ่านหน้าบันทึกการเริ่มอัตโนมัติหลังเลือกโปรไฟล์ใหม่ ไม่มีการแก้ registry/binding เอง

## หลักฐานและขอบเขต

- ก่อนแก้ production stream ของคลิปใหม่ไม่ผ่านความคาดหวัง Ready+End (`offline_audio_event_mismatch`) โดยตรวจพบ End อย่างเดียว
- หลังแก้ คลิปใหม่ตรวจ Ready หนึ่งครั้งที่ประมาณ 14.74 วินาทีและ End หนึ่งครั้งที่ประมาณ 39.03 วินาที สร้างรอบจบหนึ่งรอบใน SQLite แยก
- คลิปบวกเดิมสี่ไฟล์ยังได้ Ready หนึ่ง, End หนึ่ง และรอบจบหนึ่งต่อไฟล์ ผ่านทั้ง trial และโปรไฟล์ในซอร์สจริง
- เสียงลบจริงสามไฟล์ ได้แก่เอาหัวจ่ายออก ใส่กลับ และเสียงรถ ผ่าน production stream โดยไม่มีทั้ง Ready และ End
- WAV ต้นแบบที่มีเสียงหยอดแบงค์เป็น **บวกของ Ready** ไม่ใช่เสียงลบของ Ready ทดสอบได้ Ready หนึ่ง/End ศูนย์ แต่ไม่ถือเป็น held-out accuracy

การ replay ใช้ lease และเวลา UTC จำลอง ไม่ได้แปลงเวลา OSD เป็นเวลาจริงของเหตุ มีเสียงเงียบสังเคราะห์ 20 วินาทีต่อท้ายเพื่อรอ lookahead Ready ของคลิปใหม่ยืนยันก่อนท้ายคลิป ส่วน End ยืนยันระหว่าง tail โดยหลักฐานประกาศยังอยู่ในเสียงจริง ไม่ถือ EOF/ความเงียบเป็น End RAM ring 1,280,000 ไบต์ ไม่มี playback, upload, provider call, real RTSP หรือการอ่านฐานข้อมูล VPS ไม่ใช่การรับประกันว่าจะตรวจได้ทุกระดับเสียงหยอดหรือสภาพแวดล้อม
