# ลองเริ่มเสียง RTSP ใหม่ก่อนแจ้งเตือน

นโยบายนี้อยู่ในซอร์สที่กำลังตรวจ ยังไม่มีใน EXE V51 ที่เผยแพร่ ไม่ใช่การแก้สาเหตุ `storage_path_unsafe` ที่พิสูจน์แล้ว

## เงื่อนไข

ใช้กับตัวฟังเสียง RTSP ที่ผู้ใช้ยินยอมเริ่มไว้ เมื่อจบด้วย error หรือไม่มี PCM ที่ใช้งานได้จนเกินช่วงความสดเดิม 8 วินาที ให้หยุดเฉพาะ child เสียงนั้น แล้วรอ 15 วินาทีก่อนลองแหล่งและโปรไฟล์เดิม สูงสุดสามครั้งนอกเหนือจากการเริ่มครั้งแรก แต่ละครั้งตรวจ config, พาธและ digest โปรไฟล์ รวมถึง guards ของ storage ตามเดิม ไม่สลับไปเสียง Windows/ADB

ดีเลย์นับจากความล้มเหลวของครั้งก่อน ไม่ทำ catch-up หลายครั้งเมื่อ GUI หยุด poll ไปนาน และเริ่ม producer ใหม่ได้ต่อเมื่อ process เดิมถูกเก็บแล้ว หากยังเก็บ process เดิมไม่ได้ ความพยายามเริ่มใหม่รอบนั้นถือว่าล้มเหลวโดยไม่สร้าง producer ซ้อน ครบสามครั้งแล้วหยุดลองและเปิดการแจ้งสุขภาพ

การเรียก start สำเร็จอย่างเดียวยังไม่ถือว่าหาย ต้องมี PCM ใหม่ที่ผ่านการบันทึก เสียงเงียบที่มีข้อมูลจริงใช้ได้ ไม่ต้องรอประกาศเริ่ม/จบ เมื่อมีหลักฐานใหม่ต่อเนื่อง 30 วินาที โดยช่องว่างระหว่างหลักฐานไม่เกิน 8 วินาที จึงรีเซ็ตงบสามครั้งสำหรับเหตุถัดไป ตัวอย่างเดิมซ้ำหรือ PCM แค่ช่วงสั้นไม่รีเซ็ตงบ

## การแจ้งเตือนและหยุด

ระหว่างรอ/ลองใหม่และยืนยันการกลับมาของเสียง จะพักเฉพาะการส่งแจ้งสุขภาพช่อง audio โดยยังรายงานสถานะเสียจริง ไม่ปลอมเป็น healthy และไม่ล้าง incident เมื่อครบสามความพยายามแล้วยังไม่พร้อม จึงให้ส่งตาม grace/repeat เดิมที่ตั้งไว้ ไม่ส่งก่อนครบ grace หากยังไม่ถึงเวลา การส่ง HTTP ที่เริ่มไปแล้วไม่สามารถเรียกคืนได้

หากกลับมาปกติโดยไม่เคยส่ง fault สำเร็จ จะไม่สร้างข้อความ “กลับมาปกติ” ให้เหตุที่ไม่ได้แจ้ง การแจ้งสุขภาพภาพและการแจ้งวัตถุค้างไม่ถูกพักตามเสียง

กดหยุดหรือปิดโปรแกรมยกเลิกการลองใหม่ แหล่งหรือโปรไฟล์ที่เปลี่ยนยกเลิกการเริ่มเดิม ต้องยินยอมเริ่มขอบเขตใหม่ ไม่เริ่มเองเมื่อเปิดหน้าจอเฉย ๆ

ไม่ลบหรือย้ายข้อมูล ไม่ปิด link/root/camera/schema guards ไม่แก้คิวหรือประวัติให้เป็นจบ ช่วงเสียงขาดยังอาจพลาดประกาศและคงกติกาไม่ผูกรอบข้ามช่วงขาดเดิม
