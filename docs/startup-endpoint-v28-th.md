# SmartTapo .28 — แก้ Save startup: Windows endpoint identity unavailable

## สาเหตุตรงภาพ

ภาพที่ผู้ใช้ส่ง20:55ขึ้น**Stable Windows endpoint identity unavailable; refresh/select the saved output again** เป็นการปฏิเสธเพราะอุปกรณ์เสียงไม่มีIDที่ผูกข้ามการเปิดเครื่องได้ เกิดก่อนตรวจตัวตนAndroid ไม่ใช่บั๊กสถานะกำลังผูกค้างใน.27

พบข้อผิดพลาดในตัวอ่านของโปรแกรม: อ่านFriendlyNameจากpropertyในrawRegistryซึ่งไม่มีบนเครื่องนี้ ทำให้คืนรายการชื่อ→GUIDได้0 แม้Windowsมีอุปกรณ์ใช้งานอยู่ ไม่ใช่ให้ผู้ใช้แก้JSON/รีเซ็ตคีย์/เลือกเสียงdefaultเพื่อข้าม

เปลี่ยนเป็นอ่าน**MMDevice API ของWindows**: เฉพาะactive render output ใช้FriendlyNameและGetIdจากอุปกรณ์เดียวกัน ตรวจว่าเป็นrenderGUIDจริง ไม่สร้างGUIDจากชื่อ/เลขindex ไม่เดาผสมdescriptionกับinterface ไม่จับคู่แบบชื่อคล้าย ชื่อหรือIDกำกวม/หายจะไม่ผูกและไม่คงIDเก่าที่อาจผิดไว้

## วิธีใช้ตัวแก้

1. ปิดSmartTapoตัวเก่า เปิด`.tools/diagnostic-v28/SmartTapo.exe` เก็บconfig/data/profile/คีย์เดิมทั้งหมด ไม่ต้องลบอะไร
2. ในแท็บเสียง กดค้นหาเสียงขาออกใหม่หนึ่งครั้ง แล้วเลือกอุปกรณ์เดิมที่MEmuส่งเสียงออก เพื่อให้รายการในappมีIDใหม่จากตัวอ่านที่แก้แล้ว ไม่ต้องเริ่มรับเสียงหรือบันทึกตัวอย่าง
3. หยุดCapture/Worker/ตัวฟัง/PlaybackTESTก่อนเปลี่ยนการผูกstartup ไป**Windows startup** ตรวจเครื่องหมายยินยอมเปิดเมื่อloginและยินยอมฟังเสียงตามที่ต้องการ แล้วกด**บันทึก / ผูกการยินยอม Windows startup**และยืนยัน
4. Saveยังตรวจค่ากล้อง/ภาพช่องว่าง/profile/ADBidentity/สิทธิ์ลงentryตามเดิม ไม่มีการยอมรับอุปกรณ์ที่ระบุไม่ได้ หากผ่านแสดงผูกstartupแล้ว แต่ยังไม่เปิดฟังในรอบนั้นเอง

ไม่เปลี่ยนเสียงdefault/route/mixer/volume ไม่เลือกmicแทน ไม่แก้การอนุญาตเองและไม่ลงstartupโดยเงียบ ถ้ายังมีendpointซ้ำ/หาย ข้อความเป็นภาษาไทยให้ค้นหาและเลือกใหม่ ไม่ข้ามการผูกอุปกรณ์

## ขอบเขตยืนยัน

- ทดสอบเครื่องนี้แบบ**อ่านmetadataเท่านั้น**: ตัวอ่านเดิมได้0 รายการ ตัวใหม่ได้10ชื่อrenderที่มีGUIDไม่กำกวม ไม่เปิดAudioClient/PyAudio/stream/ไมค์ ไม่เขียนRegistry/route ไม่อ่านคีย์หรือกดSaveแทนผู้ใช้
- มีregressionทั้งmetadataจริงจำลอง/COMresources/ชนิดproperty/ชื่อซ้ำ/IDเก่า/ชื่อกับIDชัดเจน และเส้นทางUIผูกGUIDแล้วไปถึงSaveด้วยmockAndroididentityและmockregistration ไม่ได้ลงentryจริง
- ชุดตรวจEXEมีโหมดอ่านmetadataอย่างเดียวก่อนโหลดconfig/GUI/credentialstore รายงานเพียงจำนวน ไม่ใส่ชื่อ/GUIDจริงในartifact ตรวจว่ารายงานสดและไม่เปิดcapture/ลงstartup ไม่ถือว่าความสามารถอ่านmetadataเป็นการยืนยันการฟังเสียง
- **ยังไม่อ้างว่าSave/Windowsloginของผู้ใช้สำเร็จแล้ว** หรือจับเสียงตู้ได้จริง ขั้นตอนลงทะเบียนจริงเกิดเมื่อผู้ใช้กดและยืนยันเองเท่านั้น หากมีข้อผิดพลาดขั้นถัดไปให้ใช้ข้อความใหม่นั้นระบุต่อ ไม่ย้อนแก้สิ่งที่ไม่เกี่ยว

คงโหมด.27**ทดสอบฟัง Playback (TEST)**แบบรับเสียงตรง ไม่ต้องไฟล์ และปุ่มPushover.26แยกยืนยันเหมือนเดิม ดู`docs/playback-test-v27-th.md`/`docs/pushover-test-v26-th.md` การแก้IDใช้ร่วมกับการเลือกเสียงให้สองโหมดโดยไม่เปลี่ยนกฎLive/threshold/ประวัติ/เงินจริงหรือเปิดส่งAPIอัตโนมัติ
