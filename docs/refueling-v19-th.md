# SmartTapo .19 candidate — ตั้งค่าและส่งประวัติเติมไป smart-breaker

รุ่นcandidateสำหรับทดสอบในเครื่อง ผลfullsuite/clean-source/frozenGUIและSHA256ให้ตรวจreceiptที่สร้างจริง ไม่ใช่หลักฐานว่าdeployตัวรับหรือส่งไปบริการจริงแล้ว งานนี้ต่อช่องว่างจากข้อตกลงเดิม ไม่เปลี่ยนเกณฑ์จำเสียงเป็นการยืนยันธุรกรรม

## หน้าที่ของระบบ

เมื่อระบบตรวจพบประกาศที่ผ่านเกณฑ์ จะเก็บรอบในเครื่องก่อน แล้วส่งประวัติเริ่ม/อัปเดต/ผิดปกติ/จบพร้อมภาพที่เกี่ยวข้องไป API ประวัติเติมของ **smart-breaker** ตาม `refueling-webhook-api-th.md` ไม่ใช่ Pushover และไม่ใช่ notify-android ไม่ส่งเฉพาะเหตุผิดปกติ ไม่ส่ง WAV/เสียงสนทนา และไม่แต่งยอดเงินจริงจากประกาศ

ถ้าจับเสียงไม่พบ จะไม่สร้างข้อมูลว่ามีลูกค้าเติมให้เอง หากหลักฐานขาดช่วงจะไม่แต่งเวลาจบ ประวัติที่มีในเครื่องไม่ใช่หลักฐานว่าปลายทางได้รับแล้ว

## ตั้งค่าในแอป

1. เปิดแท็บ Refueling API / ส่งประวัติ ตรวจ Camera ID ให้ตรงสิทธิ์ที่ออก key ฝั่ง smart-breaker
2. กรอก **Base URL** ไม่ใช่ URL ของ endpoint ทั้งเส้น เช่น `https://dashboard.example/api` เป็นตัวอย่างเท่านั้น โปรแกรมจะต่อ `/v1/refueling/images/{id}` และ `/v1/refueling/events` ให้เอง ดังนั้นตัวรับ smart-breakerที่มีprefix `/api` ต้องมี `/api` ในBase URL ห้ามกรอกquery/token/userinfoลงURL
3. กรอก Application API key ในช่องปิดบังตัวอักษร ติ๊กอนุญาตการส่ง แล้วกดบันทึก URL/คีย์/สิทธิ์ในแอป ขั้นนี้ยังไม่ส่ง ไม่ส่ง key ในแชต ไม่แก้ JSON เพื่อใส่key ไม่ใช้บัญชี Tapo แทนapplication-key
4. การเก็บkeyใช้ Windows DPAPI ของบัญชีผู้ใช้ปัจจุบันแยกจากconfigปกติ และต้องตรงURL/กล้องที่บันทึก เปลี่ยนปลายทาง/กล้องต้องกรอกkeyที่เหมาะสมใหม่ ไม่ใช้keyเก่าส่งให้hostใหม่โดยเงียบ คัดลอกไฟล์ไปต่างบัญชีWindowsไม่รับประกันว่าถอดรหัสได้
5. เมื่อบันทึกสิทธิ์แล้ว ตรวจปลายทาง ติ๊กยืนยันการผูกคิวที่ยังไม่มีปลายทางของกล้องนี้ แล้วกดเริ่มส่ง ถ้าเพิ่งติ๊กเปิดสิทธิ์หลังบันทึกไปแล้ว ต้องบันทึกสิทธิ์อีกครั้งก่อน สถานะเริ่มส่งแยกจากเริ่มฟังเสียง เปิดแอปไม่เปิดไมค์/ฟัง/ส่งเอง และแต่ละการเริ่มส่งยังต้องมีการยืนยันชัดเจน
6. ปิดสิทธิ์/กดหยุดจะไม่เริ่มrequestถัดไป งานHTTPที่เริ่มแล้วอาจจบและปลายทางอาจรับแล้ว จึงไม่ควรถือว่าหยุดแปลว่าserverไม่ได้รับ งานยังมีผู้รับผิดชอบจนเก็บผลครบก่อนปิด

## รูปและสถานะการส่ง

- ส่งภาพจริงทีละรูปก่อน แล้วPOST JSONพร้อมรหัสรอบ/เหตุการณ์เดิม ไม่ส่งWindowspathให้serverเปิดเอง
- ยืนยันส่งสำเร็จเฉพาะเมื่อACKของreceiverตรงevent/image/hashที่ส่ง HTTP200เปล่า ๆ ไม่ใช่สำเร็จ
- retryใช้รหัสเดิม ไม่เพิ่มจำนวนลูกค้าจากการretry ข้อมูล/รูปใหม่ในเครื่องมีอายุ72ชั่วโมงตามสัญญา การretry/ประกาศซ้ำไม่ต่ออายุ ถ้าหมดอายุก่อนยืนยันต้องแสดงตามนั้น ไม่แปลว่าปลายทางไม่เคยรับแน่นอน
- HTTP401/403หยุดส่งให้ตรวจสิทธิ์/key ไม่ลองยิงถี่ด้วยkeyผิด ไม่แสดงkeyในข้อความผิดพลาด
- เปลี่ยนURL/keyไม่ย้ายคิวที่ผูกปลายทางแล้วโดยอัตโนมัติ คิวเก่าที่ไม่ได้ยืนยันต้องใช้การยืนยันย้าย/ลองส่งใหม่แยกต่างหากตามUI ไม่ส่งซ้ำงานที่ยืนยันแล้วหรือยืดTTL การย้ายคิวที่ยังไม่ยืนยันไม่ใช่เครื่องมือย้ายประวัติทั้งหมดไปserverใหม่

## ตรวจในเครื่องก่อนส่งจริง

ทดสอบด้วยข้อมูลสังเคราะห์ ตัวรับจำลอง และGUIนอกจอ ไม่ใช้keyจริง/บริการจริง/DBผู้ใช้ ภายหลังบันทึกตั้งค่าปลายทางจริงควรตรวจทั้งสถานะในเครื่องและประวัติฝั่ง smart-breaker ไม่ถือว่ามีช่องกรอกหรือbuildผ่านเท่ากับend-to-endผ่าน

## กู้หน้า Tapo จาก .18

คงแก้กู้ก่อนreconnect/Thai refresh/TTL/Stop/ชื่อกล้อง/clock/fenceเดิม รุ่น.18บนเครื่องหลักมีหลักฐานจากtypedlogว่าผ่านเส้นทางกู้อัตโนมัติและได้เฟรมใหม่ที่นาฬิกาเดิน4รอบในsessionการทำงานCaptureเดียวกัน ช่วง21:17/21:33/21:43/21:53ของ30ตุลาคม ไม่ใช่การยืนยันเสียงครบวงจรหรือผลnativeของ.19

หากเริ่มมาเจอpopupค้างโดยไม่มีหลักฐานกล้องล่าสุดยังไม่กดContinueแบบเดา ต้องเปิดLiveกล้องที่ถูกต้องใหม่ก่อนเริ่มหนึ่งครั้ง รายละเอียด `refueling-v18-th.md`
