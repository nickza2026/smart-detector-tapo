# รุ่น .39 — ปรับการรู้จำประกาศจากคลิปจริง

รุ่นนี้เป็น **candidate สำหรับตรวจใช้งานต่อ ไม่ใช่การรับรองว่า VPS/กล้องจริงเสถียรทุกสภาพ** ผลทดสอบและ hash ของ EXE ที่ส่งอยู่ใน `verification.json` ในโฟลเดอร์รุ่นนั้น ผล source อย่างเดียวไม่ใช่ผลของ EXE

## เปลี่ยนอะไร

- เก็บประกาศที่ผ่านเกณฑ์ไว้ระหว่างรอยืนยันตาม timeline ไม่ทำหายเพียงเพราะคะแนนเปลี่ยนเมื่อหน้าต่างเสียงเลื่อน แต่ยังไม่ปล่อยผลก่อนเวลา และยังทิ้งข้อมูลเมื่อเสียงขาด/แหล่งเปลี่ยน/กดหยุด
- ชุดโปรไฟล์ใหม่ตรวจทั้งความคล้ายเสียงและ **ลำดับการเปลี่ยนเสียงตามเวลา** ไม่ยอมให้เสียงที่มีสีเสียงคล้ายแต่ไม่มีรูปประโยคผ่านเพียงอย่างเดียว
- ไม่เปลี่ยนโปรไฟล์เดิมเงียบ ๆ โปรไฟล์ที่ไม่มีเงื่อนไขใหม่นี้ยังใช้เกณฑ์เดิม การใช้ชุดใหม่ต้องกดเลือกผ่านหน้าจอเอง
- หน้าฟังเสียงแยก **พร้อมเติมหลังรับเงิน / เสียงจบ / ประกาศรวม** และเก็บยอดสุดท้ายจาก worker ได้แม้ progress บางข้อความไม่ได้แสดง ตัวเลขรวมไม่ใช่จำนวนรอบเติม
- ไม่เพิ่ม Whisper ในโปรแกรม ไม่โหลดโมเดลขณะเปิดใช้งาน และไม่ใช้ข้อความที่ Whisper ถอดคลาดเคลื่อนเป็นต้นแบบเสียง

## เปิดใช้ชุดใหม่ โดยไม่ตั้งค่าภาพใหม่

1. หยุดงานและปิดโปรแกรมรุ่นเก่าตามปกติ เก็บโฟลเดอร์เก่าไว้สำหรับย้อนกลับ
2. แตก ZIP รุ่น .39 ลงโฟลเดอร์ใหม่ แล้วเปิด `SmartTapo.exe` จากโฟลเดอร์นั้น อย่าย้ายเฉพาะ EXE ทิ้ง `prepared-profile` ไว้ที่อื่น
3. ใช้ config, reference ภาพ, ROI และไดรฟ์ข้อมูลเดิม ไม่ต้องล้างประวัติหรือเลือก ROI ใหม่เพราะการอัปเดตนี้
4. ที่หน้าฟังเสียง RTSP ขณะหยุดฟัง กด **ใช้โปรไฟล์จากเสียงที่เตรียมให้** หนึ่งครั้ง รอข้อความว่าโปรไฟล์พร้อม ปุ่มนี้สร้างสำเนาชุดใหม่ที่ผูกกับกล้อง/โฟลเดอร์ข้อมูลปัจจุบัน ไม่ลบโปรไฟล์เก่า ไม่ต้องแก้ JSON หรือเลือกช่วงประโยคซ้ำ
5. อ่านข้อความยินยอมแล้วเริ่มฟังตามปกติ ไม่ใช้เสียง Windows/MEmu แทน RTSP ไม่ต้องปรับ CABLE หรือเส้นทางลำโพง

**เพียงเปิด EXE ใหม่แต่ยังเลือกโปรไฟล์เก่า จะยังไม่ได้เงื่อนไขรู้จำชุดใหม่** การยืนยัน Windows-login startup ผูกกับแหล่งและ fingerprint ของโปรไฟล์ เมื่อเปลี่ยนชุดเสียงต้องยืนยันใหม่ผ่านหน้าตั้งค่าตามปกติ โปรแกรมไม่ได้ย้าย VBS/ตั้งค่าระบบให้เองระหว่างการพัฒนา

## อ่านตัวเลขอย่างไร

- `พร้อมเติมหลังรับเงิน` คือจำนวนครั้งที่ตัวรู้จำยืนยันประกาศ “ติ้ด กรุณานำหัวจ่ายใส่ถังบีบหัวจ่ายค้างไว้แล้วกดปุ่มจ่ายน้ำมัน” ตามกติกาตู้ที่ตกลงไว้ หมายถึงรับเงินแล้ว/พร้อมเติม ไม่ใช่เวลาหยอดใบแรก จำนวนใบ หรือยอดเงินที่แน่นอน
- `เสียงจบ` คือจำนวนครั้งที่ยืนยัน “ขอบคุณที่ใช้บริการค่ะ”
- พร้อมเติม 2 ครั้งอาจเป็นรอบเดียวที่พูดซ้ำ ต้องดูจำนวนรอบและธงประกาศซ้ำในประวัติ ไม่บวกทุกประกาศเป็นลูกค้าใหม่
- พบเฉพาะเสียงจบไม่ทำให้สร้างเสียงเริ่มหรือรอบเติมปลอม
- หลังเสียงขาดอาจขึ้น **รอประกาศสิ้นสุดหลังช่วงขาดก่อนหน้า** แม้กำลังได้รับ PCM อยู่ เป็นการกันผูกลูกค้าข้ามข้อมูลที่หาย ไม่ใช่ยืนยันว่าตู้เงียบหรือไม่มีลูกค้า
- `รอข้อมูลเสียง RTSP` คือยังไม่ได้รับข้อมูล ไม่เท่ากับได้รับเสียงเงียบ

ตัวรู้จำยังรอยืนยันตาม timeline ประมาณ 13.4 วินาทีจากจุดเริ่มประกาศในชุดนี้ เวลาในเหตุการณ์ยังเป็นเวลาเสียงต้นทาง ไม่ใช่เวลาที่ตัวเลขบนหน้าจอเพิ่ม กดหยุดกลางประโยค/ก่อนยืนยันไม่บังคับ flush ให้กลายเป็นเหตุการณ์

## ผลที่วัดได้และขอบเขต

- MP4 จริงที่ส่งมามีสองไฟล์เนื้อหาต่างกัน ชุดใหม่พบพร้อมเติมและจบอย่างละหนึ่งครั้งต่อคลิป ได้หนึ่งรอบจบครบต่อคลิปในฐานทดสอบแยก
- จุดเริ่มประกาศในคลิป A ประมาณ 6.77/25.07 วินาที และ B ประมาณ 8.43/32.16 วินาที ผลยืนยันเสียงจบต้องอาศัยการต่อท้ายด้วย **เสียงเงียบสังเคราะห์ 20 วินาที** เพื่อรอ timeline ไม่ใช่อ้างว่าท้ายดังกล่าวอยู่ในวิดีโอจริง
- ลด amplitude แบบ floating-point จาก 1 ถึง 0.0001 ทั้งสองคลิป รวม 10 กรณี พบครบ ไม่ได้พิสูจน์ว่าไมค์จริงจะเก็บเสียงต่ำกว่า noise floor หรือเสียงที่ถูก quantize จนหายไปได้
- เสียงรถ/เอาหัวจ่ายออก/วางหัวจ่ายเดี่ยวที่ให้ไว้เดิม ไม่สร้างประกาศในสามตัวอย่างนั้น ไม่ใช่การวัด false-positive rate ทั่วไป
- ผสมเสียงแทรกเพิ่มแบบสร้างขึ้นที่ global SNR 20/10 dB พบครบ **9 จาก 12 กรณี** อีกสามกรณียังพลาดเสียงพร้อมเติม: คลิป A + วางหัวจ่ายที่ 10 dB และคลิป A + รถที่ 20/10 dB ค่า SNR นี้วัดทั้งคลิป ไม่ใช่ SNR ของเสียงพูดแยกจากฉากหลัง
- นำ A แล้ว B มาวางห่างกัน 120 วินาทีใน timeline จำลอง ได้สองรอบจบครบ วงเสียง RAM คงขนาดเดิม ไม่จำกัดอายุรอบเติมไว้ที่หน้าต่างเสียง 20 วินาที

ทั้งหมดนี้เป็นการทดสอบในเครื่อง ไม่ใช่ธุรกรรมจริง/การทดสอบสดบน VPS ไม่ได้เปิด RTSP จริงเพิ่ม ไม่แก้ config หรือประวัติผู้ใช้ ไม่ส่ง provider/webhook จริง และไม่แก้กติกาเสียงซ้ำ/5 นาที/การไม่ผูกข้อมูลข้าม gap

คลิปจริงใหม่ที่ช่วยตรวจต่อได้ดีที่สุดคือเสียงประกาศในสภาพต่างจากชุดที่ปรับค่า: ก่อนประกาศประมาณ 5 วินาทีและหลังขอบคุณประมาณ 15 วินาที รวมทั้งเสียงคนคุย/เพลงที่ไม่มีประกาศ หลีกเลี่ยงการเร่งเสียงหรือตัดต่อ ไม่ต้องสร้างธุรกรรมเพื่อทดสอบ
