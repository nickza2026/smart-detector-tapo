# .34 — คำนวณพื้นที่ภาพตามความถี่และเวลาเก็บ

ปิดรุ่นเก่าก่อนเปิด `SmartTapo.exe` .34 ใช้config/กรอบ/ภาพอ้างอิงเดิมเมื่อยังถูกต้อง ไม่ต้องเปลี่ยนRTSPหรือทดสอบให้แบงค์ค้างจริง กติกาtimestamp/วัตถุค้างจาก .33/.32 ยังเหมือนเดิม

## ค่าที่เห็นและวิธีใช้

ในแท็บตั้งค่า ใต้ช่วงรับภาพ มีข้อความประมาณพื้นที่ภาพ เปลี่ยนความถี่แล้วรอข้อความอัปเดต จากนั้นกดบันทึกขณะCapture/Worker/เสียงหยุดอยู่ การเริ่มroleแรกจากสถานะหยุดจะผ่านการบันทึกและคำนวณนี้เช่นกัน ไม่ปรับconfigกลางการทำงาน

สูตรจำนวนภาพที่เผื่อพื้นที่คือ:

`ceil((เวลาเก็บภาพดิบเป็นวินาที + รอบcleanup) / ช่วงรับภาพ) + 1 ภาพ`

นำจำนวนนี้คูณขนาดPNGที่ประเมินจากภาพจริง เผื่อ25% แล้วบวกภาพหลักฐาน/คิวpendingที่มีอยู่ ใช้MBฐาน1,000,000bytesเช่นเดียวกับquotaเดิม ไม่ใช้ตัวเลขขนาดภาพ1.76MBตายตัวทุกกล้อง

ตัวอย่าง0.2วินาที/เก็บ5นาที/cleanup30วินาที/ภาพ1.76MB:

- ช่วง5นาทีมีประมาณ1,500ภาพ
- รวมcleanupและเผื่ออีก1ภาพเป็น1,651ภาพ
- รวมเผื่อ25%ประมาณ **3,633MB** ก่อนบวกหลักฐานที่มีอยู่
- ถ้าเพดานเดิม4,096MBสูงกว่าอยู่แล้ว จะคง4,096MB ไม่ลดลงเอง

ถ้าเพดานเดิมต่ำกว่าที่คำนวณ โปรแกรมเพิ่มค่าเมื่อบันทึกเท่านั้น ไม่จองไฟล์เต็มโควตาบนดิสก์ทันที ถ้าเลือกความถี่/เวลาเก็บที่ต้องใช้พื้นที่เกินดิสก์ที่มี จะไม่บันทึกและแสดงเหตุผล ไม่ลดความถี่หรือเวลาเก็บแทนผู้ใช้ และไม่ขยายruntimeไปเรื่อย ๆ จนเต็มไดรฟ์

## ประเมินขนาดภาพอย่างไร

ใช้ขนาดสูงสุดจากภาพอ้างอิงและPNGเฟรมล่าสุดไม่เกิน64ตัว ตัวภาพอ้างอิงถูกวัดด้วยencoderเดียวกับCaptureหนึ่งครั้งต่อเวอร์ชันแล้วcacheเฉพาะจำนวนbytes เพราะPNGที่Pillowบันทึกอ้างอิงอาจเล็กกว่าของOpenCVหลายเท่า ไม่มีการencodeทุกpoll/ทุกเฟรมเพื่อคำนวณพื้นที่ ไม่มีการเปิดกล้องเพิ่มจากตัวคำนวณ

ถ้ายังไม่มีภาพอ้างอิง/ขนาดPNGจริง จะแสดงว่ายังไม่ทราบและไม่เดาขนาดหรือเพิ่มquotaเอง ยังตั้งค่าครั้งแรกได้ เมื่อบันทึกภาพอ้างอิงแล้วให้บันทึก/เริ่มroleแรกอีกครั้งเพื่อคำนวณ

การอ่านmetadataจำกัด100,000entries ไม่ตามsymlink/junction ถ้าเกินขอบเขตหรือเข้าถึงไม่ได้จะไม่ฝืนบันทึก เผื่อพื้นที่ว่างบนไดรฟ์อย่างน้อย1GBหรือ10%ของพื้นที่ว่างปัจจุบัน แล้วแต่ค่าไหนมากกว่า และหักพื้นที่ภาพที่จัดเก็บอยู่แล้วออกจากพื้นที่ที่ต้องเพิ่มเพื่อไม่คิดซ้ำ

## การลบภาพและขอบเขต

เวลาเก็บไม่ได้เปลี่ยนเพราะquotaเพิ่ม ภาพดิบที่Workerประมวลผลและเป็นเจ้าของแล้วเกิน5นาทีจะเข้ารอบcleanupตามเดิม ไม่ลบหลักฐานวัตถุค้าง/แจ้งเตือนที่ยังรอส่งเพื่อบีบให้พอดีquota ไม่ลบmarkerเก่าหรือไฟล์ที่ยังไม่ถูกประมวลผลโดยเดา

ทดสอบvirtual clockขอบ5นาทีและหลังขอบ,rawที่เป็นของWorker,unprocessed input,evidenceและnotificationfailedในSQLite/tempที่แยกไว้ ไม่เปิดฐานข้อมูลจริง ไม่ลบไฟล์ผู้ใช้ ไม่เชื่อมRTSPหรือส่งproviderจริง การลบตามเวลาเกิดเมื่อWorkerทำงานและถึงรอบcleanup ไม่ใช่บริการลบภาพแยกขณะปิดโปรแกรม

นี่เป็นการประมาณตามภาพที่วัดได้และค่าที่เลือก ไม่รับประกันขนาดภาพอนาคต/หลักฐานสะสมทุกเหตุการณ์ หากภาพเปลี่ยนความซับซ้อนมากหรือมีไฟล์ที่ไม่เข้าเงื่อนไขcleanupสะสมยังชนเพดานได้ quota/freespaceguardยังอยู่ ผลfull/clean/frozenและhashอยู่ใน `verification.json` โฟลเดอร์ส่งมอบ ไม่มีcommit/push/deployหรือการเปลี่ยนconfigจริงระหว่างพัฒนา
