# SmartTapo .27 — ฟังเสียงจาก Tapo Playback โดยตรง (TEST)

## แก้ความเข้าใจผิด

การทดสอบที่ผู้ใช้ต้องการคือเปิดย้อนหลังในTapoบนMEmuแล้วให้โปรแกรมรับเสียง ไม่ใช่เตรียม/export/อัปโหลด/เลือกไฟล์ WAV โหมดนี้จึงรับเสียงขาออกที่เลือกโดยตรง ส่วนเครื่องมือไฟล์เดิมเก็บไว้เป็น**ไฟล์ WAV (ทางเลือก)** ไม่ใช่ขั้นตอนบังคับ

## เริ่มทดสอบ

1. ปิดSmartTapoตัวเดิม เปิด`.tools/diagnostic-v27/SmartTapo.exe`
2. ผู้ใช้เปิดPlaybackในTapo/MEmuและเล่นช่วงที่ต้องการด้วยตัวเอง แนะนำความเร็วปกติ โปรแกรมไม่กดสลับหน้า/เลือกวันย้อนหลังให้เอง
3. ไป**เสียง MEmu / ฟังเติม** แท็บแรกค้นหา/เลือกเสียงขาออกWASAPIloopbackที่MEmuใช้ หากเคยผูกGUIDไว้ต้องrefreshเพื่อตรวจรายการจริงก่อน ไม่เลือกdefault/micแทนเมื่อหาอุปกรณ์เดิมไม่พบ
4. ไป**ทดสอบฟัง Playback (TEST)** ดูชื่อเสียงขาออกที่เลือก กด**เริ่มทดสอบเสียงจาก Playback**และยืนยันการรับเสียงครั้งนี้ ไม่ต้องเลือกไฟล์เสียงหรือJSON ถ้ายังไม่เลือกoutputมีปุ่มพากลับแท็บเลือกเสียง ใช้profileเดิมที่เลือก/ผูกกล้องเดียวกัน หรือเตรียมprivateprofileจากเสียงตัวอย่างที่มีให้
5. ระหว่างทดสอบดูreceivedPCM/RMS/peak, คะแนนวลีที่ผ่าน, ค่าสูงสุดwindowล่าสุดและเหตุที่ยังไม่ผ่าน, จำนวนวลีและช่วงห่างเริ่ม–สิ้นสุดTEST โปรแกรมไม่ใช้ระดับRMSเป็นเกณฑ์ใหม่ในการรับวลี คะแนนNCCไม่ใช่เปอร์เซ็นต์ความมั่นใจ
6. กด**หยุดทดสอบ**เมื่อพอ หรือหยุดหลัก/ปิดโปรแกรมจะหยุดและเก็บchildที่โปรแกรมเป็นเจ้าของ ไม่เริ่มรับเสียงใหม่เอง ไม่ต่อสถานะข้ามการเริ่มทดสอบคนละรอบ

ต้องหยุดตัวฟังLive/Probeรับเสียงอื่นก่อนเริ่มTEST และห้ามเริ่มตัวฟังสองโหมดพร้อมกัน เลือกoutputชัดเจนไม่เปลี่ยนroute/volumeWindows โปรแกรมไม่แยกเสียงTapoจากแอปอื่นที่ออกอุปกรณ์เดียวกัน จึงไม่ยืนยันว่าเป็นเสียงกล้องใดหรือหลักฐานเงินจริง

## อ่านผล

- ก่อนมีPCMจริงแสดงunknown/unreceived ไม่ใช้0ปลอม ถ้าได้รับPCMเงียบจริงจึงมีระดับ0ที่วัดได้ ระดับเสียงมีไม่ได้แปลว่ารูปแบบเสียงตรงprofile
- รับต่อเนื่องจนผู้ใช้หยุดหรือเกิดข้อผิดพลาด ไม่มีรอบ10/20sตัดการทดสอบ มีเพียงwindowNCC20sที่เลื่อนพร้อมstateTESTซึ่งอยู่ข้ามหลายนาทีได้
- Offsetนับตั้งแต่เริ่มรับเสียง ไม่ใช่วันเวลาเก่าที่แสดงในTapo ไม่ผูกกับจำนวนเงิน/จำนวนลูกค้า
- คะแนนwindowล่าสุดไม่ใช่วลีที่ยอมรับ ไม่ใช่รายการเงินจริง และไม่ใช่ทุกpeakที่ถูกปฏิเสธ ส่วนacceptedTESTต้องผ่านเกณฑ์เดิม/anchors/onset/lookahead/overlap/duplicateก่อน ไม่ลดthresholdหรือปลดLiveguardของงานจริง
- Readyที่ยังไม่มีendคงpending ไม่สร้างendเมื่อหยุด/ข้อมูลขาด/หมดเวลาอ่าน พบendไม่มีreadyไม่สร้างstartย้อนหลัง ถ้าเริ่มหลายครั้งก่อนendแสดงกำกวม ไม่เดาว่ารอบเติมเสร็จ
- ข้อมูลผิด/อ่านไม่ครบ/อุปกรณ์เปลี่ยน/ไม่รับข้อมูล/driverค้างทำให้หยุดและผลค้างไม่ครบ ไม่เติมsilenceเพื่อเชื่อมช่องว่างที่ไม่ทราบ ไม่เลือกอุปกรณ์อื่นแทนและไม่retryรับเสียงเอง
- ข้อมูล/ผลที่แสดงถูกจำกัดเพื่อคุมRAM แต่stateและจำนวนวลีทำต่อในworker ไม่ยกอายุstateเท่ากับขนาดwindow ข้อมูลผ่านIPCเป็นmetadataเท่านั้น ไม่ส่งPCMออกจากchild ไม่บันทึกเสียงลงดิสก์/อัปโหลด

TESTไม่สร้างproductionLiveLease/ประวัติ/รายการเงินจริง/DB/outbox/API/Pushover ไม่เปิดแจ้งเตือนอัตโนมัติ ปุ่มPushoverจริงของ.26ยังเป็นอีกการยืนยันแยก ไม่ใช่ผลของPlaybackTEST

## Save Windows startup

แก้กรณีที่อ่านตัวตนAndroidไม่สำเร็จแล้วแท็บstartupค้างว่า**กำลังผูก…**: ตอนนี้แสดง**ยังไม่ผูก startup: เปิด MEmu และ ADB ที่เลือกไว้ให้พร้อม…**ทั้งในpanelและสถานะหลัก ไม่มีการลงทะเบียนหรือเปลี่ยนconfigเมื่ออ่านไม่สำเร็จ และยังเคารพcancel

นี่แก้บั๊กสถานะที่พิสูจน์ด้วยmockแล้ว **ยังไม่ได้พิสูจน์ว่าสาเหตุเดียวกับการบันทึกที่ผู้ใช้แจ้ง** ต้องมีข้อความที่ขึ้นเมื่อกดSaveเพื่อแยกค่าที่ยังไม่บันทึก/ภาพช่องว่างไม่พร้อม/งานกำลังทำอยู่/เสียงหรือprofileไม่ตรง/ADBidentity/สิทธิ์ลงentry ไม่ข้ามvalidationหรือบันทึกstartupจริงระหว่างพัฒนา

หากโหมดฟัง/PlaybackTESTทำงานอยู่ ต้องหยุดก่อนเปลี่ยนการผูกstartup ตามกติกาเดิม Startupที่ได้รับอนุญาตยังเป็นLive+Capture/Worker+เสียงเดิม **ไม่เริ่มPlaybackTESTเมื่อboot/loginเอง** รุ่นส่งมอบไม่ยืนยันactualWindowslogin/phoneAck/เคสเสียงจริงที่พลาด
