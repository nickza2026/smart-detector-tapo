- “ขอบคุณที่ใช้บริการค่ะ” ให้ถือว่าจบรอบ ไม่มีการเดาจบจากเสียงหัวจ่ายวางกลับ ความเงียบ หรือครบtimeout
- หากเงียบเกิน5นาทีให้เป็นรอบมีปัญหาและระบุว่าไม่พบเวลาจบ ข้อความแนะนำ **“ไม่พบเสียงจบภายใน 5 นาที”**; ช่องเวลาจบแสดง **“ยังไม่พบเวลาจบ”** และไม่มีtimestampจบที่สมมติขึ้น เวลาพบปัญหาต้องเป็นคนละค่ากับเวลาจบ
- เมื่อมีเสียงขอบคุณภายหลัง ให้ใช้เสียงนั้นยืนยันเวลาจบจริงตามกติกาผู้ใช้ แนวทางที่เสนอคือเก็บธง/ประวัติปัญหาที่เคยเกิดไว้แม้รายการจบภายหลัง ไม่เปลี่ยนย้อนหลังว่าปกติตลอดรอบ
- **ผู้ใช้ยืนยัน22:25BKKแล้ว:** นับ5นาทีจากเสียง “กรุณานำหัวจ่าย…” **ครั้งล่าสุด** ทุกประกาศซ้ำจริงเริ่มนับใหม่ แต่เสียงรถ/คนคุย/หัวจ่ายกระแทกไม่รีเซ็ตเวลา ไม่ถามจุดนับนี้ซ้ำ
- ไม่ตีความtimeoutของตัวเฝ้าเป็นการยกเลิกจากตู้ และไม่ถือว่าได้จ่ายน้ำมันครบ/ได้เงินเท่าใดจากความเงียบ การรับเสียงขาดหายต้องแยกสุขภาพแหล่งเสียง ไม่อ้างว่าตู้เงียบจริงโดยไม่มีข้อมูล

## แนวทางที่เสนอ ยังรอยืนยันรายละเอียด

- ใช้แม่แบบเสียงประกาศเริ่ม/จบจากตู้จริงและ negative samples ไม่ใช้แค่เสียงดังเกิน threshold ไม่ต้องนับเสียงเหรียญเพื่อกำหนดจำนวนรายการเติม
- เพิ่ม worker ฟังต่อเนื่องพร้อมสถานะสุขภาพ/การขาดข้อมูล แยกจากเครื่องมือเก็บตัวอย่าง10วินาที ไม่ประกาศว่ารับเสียงต่อเนื่องบน VPS หลังออกRDPได้จนกว่าจะทดสอบจริง
- บันทึก DB ในโปรแกรมและคิวส่ง webhook ก่อน แล้วให้ dashboard รับ/จัดเก็บผ่าน API ของตนเอง ส่งเหตุเริ่มและจบพร้อมรหัสคงที่ รองรับ retry โดยไม่ซ้ำ การดูภาพจาก dashboard ต้องมี upload/API ที่ยืนยันสิทธิ์ ไม่ใช่ Windows path
- เก็บข้อมูลหยอดแบงค์เดิมไว้เป็นหลักฐานเดิม ไม่แปลงเป็นการเติมสำเร็จย้อนหลังโดยไม่มีเสียงยืนยัน ผูกภาพกับ lifecycle/retention ของประวัติเติม ไม่ให้ถูกล้างโดยรอบหลักฐานชั่วคราวที่ไม่เกี่ยวข้อง
- ถ้าพบเสียงเริ่มแต่ไม่มีเสียงจบเพราะข้อมูลขาด ให้แยก incomplete/รอตรวจสอบ ไม่สร้างเวลาจบหรือยอดเงินขึ้นเอง

## ตัวอย่างที่ได้รับและข้อกำหนดเสียงแทรก

- ผู้ใช้ส่งไฟล์ใน `sound/` แล้ว2ไฟล์: ตอนจบ และตอนเติมที่มีเสียงหยอดแบงค์แทรก แต่ละไฟล์10วินาที PCM16 stereo44.1kHz ไม่พบ sample ชนเพดานดิจิทัล ต้นฉบับคงเดิม ไฟล์จริงถูกกันออกจากGit/การเผยแพร่โดยปริยาย
- ผู้ใช้ยืนยันต้องรองรับเสียงรบกวน เช่น ตอนเอาหัวจ่ายเข้า/ออกจากตู้ และเสียงหยอดที่ทับประกาศ ดังนั้นห้ามใช้ loudness/เสียงติ้ดอย่างเดียวเป็นเหตุเปิดหรือปิดรายการ และไม่ควรใช้เสียงแทรกในคลิปเป็นลายเซ็นของคำประกาศ
- ทดลองออฟไลน์: antialias/downsample8k, spectral/mel features150–3500Hz, ปรับ noise floor รายย่าน/จำกัดอิทธิพลช่วงพุ่งแรง/normalize และเปรียบเทียบรูปแบบต่อเนื่อง ไม่แก้หรืออ้างว่าลบ noise ออกจากต้นฉบับได้หมด
- ผล calibration/augmentation บน2ไฟล์เดิม: ระดับเสียงลด20dBยังจับตำแหน่งเดิมได้; เพิ่มเสียงแทรกสังเคราะห์ที่20/10dBยังได้ตำแหน่งเดิม เสียงกระแทกสังเคราะห์/short cue อย่างเดียวได้ similarityต่ำกว่าแม่แบบ แต่เสียงเริ่มมีบางช่วงคล้ายแม่แบบจบ และที่ interferenceแรงเท่าเสียงเป้าหมายคะแนนเริ่มลดลงมาก การลดthresholdเพื่อรับทุกกรณีมีความเสี่ยงจับผิด จึงยังไม่กำหนด production threshold
- นี่ไม่ใช่ held-out test หรืออัตราความแม่นยำ ช่วงแม่แบบเลือกจากสัญญาณ/สเปกโตรแกรมโดยประมาณ ยังไม่ได้ยืนยันคำและขอบเขตด้วย transcript ไม่มี negative recording จริงที่ยืนยันว่าไม่มีประกาศหรือรอบเติมอิสระเพิ่ม จึงยังไม่เปิด live detection/history/webhook
- ต้องมีช่วงหัวจ่าย/หยอด/มอเตอร์ที่ **ไม่มีประกาศ** เพื่อทดสอบ false starts/false ends และรอบประกาศอิสระเพิ่มเติมเพื่อตรวจ generalization ไม่ใช้การเทียบไฟล์กับตัวเองเป็นหลักฐานว่าทำงานได้ทุกครั้ง หากเสียงประกาศถูกกลบจนไม่พอให้ยืนยัน ควรแสดงไม่แน่ใจ/ข้อมูลไม่ครบ ไม่เดาปิดรายการสำเร็จ
- หลักฐานตัวเลข/ภาพสัญญาณและขอบเขตการทดลองอยู่ `.tools/refueling-audio-analysis/` เป็นข้อมูลทดลองส่วนตัว ไม่ใช่ runtime model หรือ EXEรุ่นใหม่
